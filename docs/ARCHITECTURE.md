## 用户侧与世界服务的分工

用户侧负责目的、提示词约束、模型选择、私人记忆与上下文、推理及工具调用。执行载体可以更换；这些资料由用户保管和迁移，Runtime 不接管它们，也不判断某次行动是否符合用户的真实意愿。

世界服务接受结构化调用，验证凭据所代表的主体和世界 scope，执行世界开发者声明的规则，并持久保存已成立的世界结果。用户给工具的“不要发私聊”等提示词约束由用户／宿主处理；世界声明的“非参与者不能读取私聊”由服务器验证。两者不能统称为服务器管理的 Agent 权限。目标或笔记可以作为用户主动提交的世界业务数据保存，内核不因此成为用户目的管理器。

服务不保存 Agent 内部运行状态；世界数据、身份映射、凭据和回执仍是持久状态。当前 MCP 通信另有进程内会话绑定，重启后可重新初始化；它不是模型对话或私人记忆，也不构成独立 Agent 身份。严格的部署无状态／多副本方案不是当前已实现事实，具体映射见 [IMPLEMENTATION](IMPLEMENTATION.md)。

## Shared Grove 的当前组合边界

当前持续创生轮保留原解释器、阶段快照、数量与容量约束和Runtime原子提交，新增三个明确的连接边界。作者可公开有类型的自定义字段，消费者端口固定不可变来源定义与类型；第三位作者可发表局部安装的接触交互，只有合法安装到实际容器后才生效，不能自动改写全世界。公开字段和安装引用不授予对其他对象的写权限，也不生成物资。

已保存实例与当前计算前沿分离。执行依赖从不可变声明推导，输入或可见性变化唤醒相关实例；已结算的安全字段规则可以休眠，材料、机械、反馈等状态机制保守保持活动。邻近事件按实际发生位置分配给消费者，各自待处理序列引用同一持久事实；缺输入或队列溢出暂停本地消费，不阻塞近期公共记录的保留，全局事务容量上限仍保留。解释语义固定为`grove.program.v1`，旧无标记定义按同一语义读取，原正文和哈希不变，未知语义拒绝。

这一轮移除静态创造成果永久占活动位、全局事件保留被最慢消费者卡住的结构问题。仍使用单世界时钟和同一SQLite事务，仍限制同时活动前沿与物理闭包。后续多域执行必须按真实材料、容器、机械和事实依赖划分，并处理跨域交接、时序和恢复；不能仅按地图区块轮流跳过计算来宣称规模能力。现行验证与剩余限制见[当前研发记录](SHARED_GROVE.md#当前研发记录)。

官方世界采用普通中心权威服务器。对象、实际材料批次、物理关系和过程统一结算，人和 Agent 行动、程序生成及内容贡献经过同一世界提交边界。World Package 提供可选模拟层与可信的有界声明程序解释器：条件、状态变迁、反应、持续过程和对象连接可由合法声明定义，不执行作者提供的任意 Python／JavaScript。合法定义自动发表，定义及版本引用不可变，已有对象固定引用版本；中立 Runtime 不内置材料、玩家、工具用途或这些世界机制。

模拟执行以固定阶段快照和受限效果计划工作，统一分配来源数量与目的容量，再合并脏状态，通过现有Command／Scheduled Effect一次原子提交。每phase的非事件规则按rule.id执行一次；事件规则以事件sequence为外层，同事件按rule.id排序。when读取该phase快照，effect逐条更新候选状态；本步产物的输入额度到下一逻辑step才开放。反应使用真实残余量、原子反应程度与目的容量，独立反应竞争来源，同族替代反应排他。依赖和独占写入冲突有明确拒绝边界，不递归立即回调改权威状态。对象树、批次、活动闭包与序列化字节在接纳时受限，保留Runtime原提交边界；准确限额属于L6。

机械按一网络一source、齿数与方向比、扭矩、有限能量、负载及行程计算，有界声明字段可提供负载／速度输入，统一冻结network snapshot、求解、提交。循环、双source、过载或能量耗尽等机械求解停止保留当前位置与角度，且不消耗新能量；动力燃烧真实木料。机械位置由solver独占写入；声明可以读取机械／事件状态并改变获准authored fields，不能写owner、普通position或安全字段。该模型不宣称惯性、重力或碰撞应力。

真实公共事件先进入journal。记录器启用后，按获准半径与逻辑tick窗口持久记录；occurred、recorded与read_by独立，私人事实不进入公共记录。世界合同固定条款，由真实actor接受，服务器实际完成条件结合材料交付、事件与逻辑期限形成完成、失败和释放；托管材料不能被规则反应消费。作者不能替另一主体接受，沉默不产生同意。这些对象复用状态、Operation／Receipt和事件，不新增通用审批内核。

声明运行越界隔离为该实例的过程错误，不停止整个世界。机械成功后，`after` 声明错误保留已求解的机械结果，只回滚该实例的声明字段与材料变化；不宣称所有程序错误都会触发整网原子回滚。修复实际字段要经过合法声明动作或新版本实例，不修改已发表版本。

本机OpenCode连接器是用户自己的Agent／外部工具的Client。工具在有效显式目标下理解本机意图和偏好，读取当前事实、贡献和结果，执行实际读取、计划、行动、读回与适应，也可创作及接续内容。没有目标时不因世界变化自动推理。公共内容是锚点／贡献／结果引用，不是统一任务阶段或第二份模拟事实。私人上下文留本机，不从A复制给B。

网页提供人的移动、装卸、绑定与使用，以及明确的目标委托、控制状态和收回入口。Agent 在有效世界控制授权内操作同一角色，普通提问不隐式授予控制。收回阻止未来未执行动作，已提交的事实不回滚；原未知结果继续查回执。同一 control bearer 不能证明请求来自人还是模型，世界控制授权也不构成 Agent 本体认证。普通地面公开，背包与出生安全区保护，作者来源不是产权。首次回应与世界读取是客户端入场门槛，不增加 AgentIdentity。

创作使用实际公开机会、当前规则目录／schema和区域资源；受限蓝图会话是创作子步骤，不能作为整个委托路径的禁行动合同。实例提交重新验证关键语义并消耗真实资源与机会预算，定义发表不等于实例已创建，普通提问不发表。单人一个任务，只有有效目标驱动继续推理；实际变化供读取和适应，他人发表只刷新事实，不产生无目标唤醒。主身份／会话接续，未知结果继续原Operation／Receipt。

物理过程、记录窗口和合同期限均由世界逻辑 tick 推进；停机暂停，重启接续，不追赶墙钟。连接超时与生成机会租约是运维资源边界。模型在外部宿主运行，不随每个物理步调用。

## 组件责任

| 组件 | 必须承担 | 不应承担 |
| --- | --- | --- |
| Identity Core | 保存／验证参与身份与调用凭据的运行时事实，向执行核心提供已验证 Principal。 | 决定具体世界的业务资格。 |
| Runtime Execution Core | 执行 Query / Command、授权链、状态提交、Receipt、通知及可选运行时效果。 | 解析自然语言意图、运行模型推理、硬编码某个世界玩法。 |
| World Authoring Boundary | 让世界声明动作、状态约束、授权、投影、共享观察、持久时间等规则。 | 启动 Web 服务、管理用户私人模型上下文。 |
| Observation / Projection | 计算授权 View、读取通知／Stream、维护可重建同步位置。 | 成为第二份权威业务状态。 |
| Scheduler / Maintenance | 驱动已经提交的 Scheduled Effect 和有界数据保留工作。 | 代替用户或 Agent 产生新意图。 |
| Gateway | 把不同传输映射到同一个 Runtime 行为合同，规范 schema 与错误语义。 | 复制一套 transport-specific 世界规则。 |
| Transport Adapters | 处理 HTTP、MCP 或未来其他传输的编码、鉴权入口和生命周期。 | 自己决定业务是否完成。 |
| Composition Root | 选择 World Definition / World Instance，组装 adapters、workers、Runtime 和部署配置。 | 重写 Runtime 提交语义。 |
| World Package | 通过公开作者边界提供领域规则、声明解释器、版本定义、过程／机械结算与内容。 | 执行任意作者脚本、托管模型或反向成为 Runtime 固定玩法。 |
| Client / Agent Host | 管理用户授权、外部推理、委托行动读回、停止、连接、缓存和表现。 | 绕过世界规则或通过本地 UI／模型总结制造服务器事实。 |

## 依赖方向

关键边界不是要求整个仓库只有一条 import 链，而是防止低层权威逻辑依赖上层适配与具体消费者。

- Runtime Execution Core 可以依赖共享合同／声明类型和内部能力模块，但不能依赖 HTTP/MCP/Web、具体 World Package 或测试项目。
- 可移植 World Package 应依赖公开作者边界，而不是 Runtime 私有模块、adapter 或管理 UI。
- Gateway / Transport Adapters 可以依赖 Runtime 和身份解析；Runtime 不反向依赖它们。
- Client 通过公开传输合同工作，不应需要数据库或 Runtime 私有对象。
- Composition Root 可以依赖多个组件，因为它的职责就是组装，而不是被误当成“纯核心”。

当前静态 import guard 只防止明显反向依赖；动态导入和运行时猴子补丁不在该测试能力范围内。

## 事务与一致性边界

Runtime 管理的 Command 写入必须汇聚到一个权威事务边界。普通外部 Command 与 Scheduled Effect 最终应复用同一提交语义，使状态、Receipt、通知、Stream 发布和后续定时命令不会分别成功。

授权 Query / View 使用一致读取边界观察世界事实；可重建 cache 在读取之后维护，不能成为提交前提。

并发执行可以有多个进程或 worker，但最终写入必须通过存储／fencing 协调，使旧租约、重复 Operation 和并发 timer 不产生两套已提交权威结果。

## 写入路径

1. Adapter 接收结构化请求和凭据。
2. Identity Core / auth boundary 解析 Principal 与访问模式。
3. Gateway 把请求映射为同一个 Query / Command 合同。
4. Runtime 取得所需事务／fencing 边界，校验动作、版本、授权与参数。
5. World Package 的声明规则产生候选世界变化与 Runtime 管理效果。
6. Runtime 校验候选结果并在提交前重查会影响资格的身份／租约。
7. 同一提交边界内的权威效果一起提交或一起回滚。
8. Adapter 只编码已形成的结果；响应丢失后的恢复仍由 Operation / Receipt 语义处理。

## 读取与表现路径

Query、View、Notification、Stream 都从当前权威事实和当前权限出发。Client 可以缓存、排序、投影和动画，但这些派生层没有特殊旁路去修改权威状态。

View 投影保持单一数据库读取快照；固定该次世界代码、状态授权与流定义后，读取不持续占用世界写入锁。返回或保存派生检查点前，重新校验当前身份、世界代码和视图授权；并发变化不拼入旧快照，撤权或代码替换使该次结果失效。未变化的检查点复用也遵守这一步。

公共记录器只消费真实且获准的已提交事件；发生、被记录与由某主体读取分别保存和投影，不从模型叙述或私人缓存补造历史。

表现信号可以随已提交事实产生；动画是否播放完不进入 Runtime 的业务提交链。

## 信任边界

### 外部输入

客户端、Agent 输出、自然语言 payload、选择器和资源引用都是不可信输入，必须经过 schema、身份、授权和大小边界。

### 身份密钥与世界本地凭据

用户身份私钥是用户自己的根控制材料，Runtime／世界只接收公钥和针对新鲜 challenge 的签名，不保存身份私钥。公钥是跨世界稳定身份；世界本地档案、权限和 bearer Credential 都不是身份密钥本身。

世界完成持钥证明后，只在自己的 Identity Core 中保存 `公钥 → 本地 Principal/Profile` 映射，并签发本世界 scope 的调用 Credential。Bearer Credential 是秘密调用材料，应由宿主管理并在鉴权层使用；世界规则只需要得到已经解析的 Principal／访问信息，不应依赖把 bearer secret 或身份私钥复制到世界状态。

### World Package

**当前架构把被加载的 World Package 当成部署方信任的代码。** 业务层的 World Instance 隔离不等于敌对租户安全沙箱。

世界内作者发表的声明程序只由有界解释器读取，不成为可执行 Python／JavaScript。解释器属于受信 World Package；这不扩大为任意第三方代码沙箱，也不让声明取得受保护字段写权。

如果未来产品要在同一宿主中执行互不信任的第三方世界代码，就必须引入独立的进程／权限／存储或真正的沙箱边界；不能靠现有 scope 字段或 SQLite authorizer 宣称完成安全隔离。

### 主机与权威存储

拥有进程、数据库文件、备份或主机管理权限的一方处在应用层授权之外。应用权限不能防止主机管理员直接读取／修改底层数据。

### 外部系统

付款、网络写入、文件和其他外部副作用处在 Runtime 内部事务之外。需要跨系统一致性时必须建立明确的幂等、outbox、交付或补偿架构。

## 未来架构变化的判定

文件拆分、函数重命名或换数据库不一定改变 L5。只有组件责任、信任域、提交边界、依赖方向或进程／隔离模型改变时，才算技术架构变化。

## EigenFlux 参考建议

宿主安装／连接检查、稳定本地配置、取消与重连属于外部宿主／adapter 责任；身份验证、世界授权、提交、Receipt、Snapshot 与同步恢复继续走现有 Runtime 路径。参考 Agent Home 的价值在于稳定隔离身份／配置，而不是引入 EigenFlux CLI、Redis、Elasticsearch 或另一套 Agent 框架。

通知／推送只作为低延迟发现手段，权威恢复仍依赖当前状态、Receipt 和可验证的同步合同。以后若确有容量或跨主机需求，再依据观测到的瓶颈引入消息总线或新服务；不能因为参考项目采用微服务就提前复制其部署形态。
