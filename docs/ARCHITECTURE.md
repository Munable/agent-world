# L5：技术架构

本文定义技术责任、依赖、事务与信任边界。Agent World 原生面向 Agent；Agent 交互与人类交互按各自消费者契约组织，共用唯一世界权威。当前代码、存储、接口名称和数值映射见 [IMPLEMENTATION](IMPLEMENTATION.md)，可执行接入见 [INTEGRATION](INTEGRATION.md)，实际验证与失败见 [当前研发记录](SHARED_GROVE.md#当前研发记录)。

## 五个责任

| 责任 | 必须承担 | 不应承担 |
| --- | --- | --- |
| 世界内核与世界规则 | 验证身份与世界资格，解释合法行为，保存共同事实，形成唯一提交与 Receipt，执行已声明的世界过程。 | 托管模型推理、私人记忆、私人目标或宿主预算；依赖某个前端或宿主。 |
| Agent 交互契约与可复用客户端 | 提供能力发现、获准事实与 schema、结构化行动、证据读取、错误分类和恢复；复用操作身份、分页、同步与结果核对。 | 另建世界规则、推断未交付事实、把模型文字认证为完成，或绑定某个模型会话。 |
| 宿主 adapter | 把可复用客户端接入具体外部工具，管理私人上下文、请求用途、用户授权、推理预算、取消、停止与本机未决操作。 | 镜像一套世界状态、替世界判断资格、把工具身份当作世界身份。 |
| 人类交互 API | 双向表达获准事实、当前选择、参数约束、拒绝与后果，并接受人的结构化意图。 | 接管私人推理、依赖具体画面，或复制动作合法性与提交规则。 |
| renderer | 翻译人类语义接口为地图、文字、语音或其他呈现，收集输入，显示真实控制与恢复状态。 | 解析作者程序来裁决资格，访问私有存储，或通过动画制造世界后果。 |

这些责任不是五个必须独立部署的服务。实现可以同进程组合；边界由合同、依赖与权威决定。HTTP、MCP 都是 API 接入方式，不能把 MCP 归入“Agent 内部”、把其他 API 归入“外部”后复制不同业务规则。

OpenCode 与二维网页是当前 reference adapter。它们证明的范围分别记录；其他宿主、模型与前端不会因为责任已定义就自动获得验证结论。

## 唯一世界权威

世界内核提供身份解析、Query／Command 执行、授权链、事务、版本、Operation／Receipt、事件、持久时间与观察基础。World Package 通过公开作者边界声明领域对象、行动、授权、投影和规则。世界内核保持领域中立，领域规则不因被官方世界先使用就进入全部世界。

Agent 与人类可以需要不同的获准投影、发现颗粒和输入方式。两类 API 必须复用同一身份、资格、动作定义与提交路径；同一行为的当前条件、拒绝与后果只能由世界规则形成。可用菜单或发现结果是一份观察，不是预先承诺之后必定成功。

Gateway 与 transport adapter 负责协议编码、schema 映射、鉴权入口和连接生命周期。它们把请求交给共同执行边界，只编码已经形成的结果。不同传输的请求和恢复不产生另一套 Operation／Receipt。

身份核心只证明调用者与凭据，不决定领域资格。投影与同步只派生授权事实；scheduler 只执行已提交的定时机制；composition root 负责选择世界、组装组件及部署配置。这些支撑责任不改变五个消费者与权威边界。

## 用户侧与世界服务

用户与外部宿主决定目的、提示词、模型、私人记忆、运行预算、授权和停止。用户给工具的“不要发私聊”由宿主处理；世界的“非参与者不能读取私聊”由服务验证。私人授权与世界资格需要同时成立，不能统称为服务器管理的 Agent 权限。

世界保存身份映射、凭据及授权的世界事实、业务状态和回执。用户可主动把目标或笔记提交为世界业务数据，但这不把内核变成私人目的管理器。协议会话与连接状态也不等于模型对话或 Agent 本体。

宿主 adapter 通过可复用客户端管理读取与写入恢复，私人材料留在用户侧。人类交互 API 从世界获准投影取得事实；宿主状态接口只表达实际连接、请求、授权与原回执关系，不能成为当前对象或过程状态的第二份存储镜像。

## Agent 交互路径

Agent 的首要路径是发现当前可用能力，按需读取规则、schema 与事实，绑定本次获准观察，提交结构化行动，核对 Receipt 与后果，并按错误语义恢复。能力说明、发现样本、完整事实和行动资格必须可区分；展开与分页依正式读取关系进行，不能从名字、旧记忆或未交付内容补全。

可复用客户端提供与具体模型无关的请求构造、操作身份保存、错误分类、回执恢复、分页与同步能力。宿主 adapter 再把这些能力映射为工具和请求上下文，管理本机日志、模型输入预算、任务接段及停止。客户端恢复世界事实，宿主决定是否继续推理；世界变化本身不授予新目标或预算。

本机审计保存失败、未知写结果、无法确认原推理停止或缺少原授权关联时，adapter 封闭后续受托行动。安全接续需核对原请求、排空本机发送、恢复原回执、获得当前现场并保存恢复事实。不能靠新任务、新操作身份或预算重置掩盖原结果。

具体交互语义见 [AGENT_INTERACTION](AGENT_INTERACTION.md)。

## 人类交互与呈现路径

人类交互 API 由 World Package 定义版本化语义合同，表达世界与主体范围、同一读取快照的水位、事实的可知性与时间范围、解析后的外观、当前动作、候选、参数护栏及结构化意图。它不暴露私有实体存储或作者程序结构作为前端裁决依据。

renderer 读取这份合同，显示事实与选择，收集参数并提交服务器描述的意图。原动作 handler 继续负责授权、当前条件、版本和后果提交。Agent 的事实与创作接口按 Agent 需要保留；人类投影不替代 Agent 原始行动证据。

读取水位用于防止乱序展示，不能替代对象版本、动作观察、固定参数或 Receipt 提交顺序。接口版本不受支持时阻止新意图，仍保留原未知 Operation 的恢复通道。人的已编辑输入不随刷新偷偷改换参数或来源。

具体表达规则见 [PRESENTATION](PRESENTATION.md)。

## Shared Grove 的世界规则边界

Shared Grove 使用中心权威世界。人类行动、Agent 行动、程序生成与内容贡献经过同一对象模型、规则及提交边界。定义发表与实际创建分离；实例创建重新验证当前关键条件，消耗真实资源与机会预算，来源引用不生成物资或授予写权。

World Package 提供可信、有界的声明解释器与可选模拟层。条件、状态变迁、反应、持续过程、对象连接和局部安装交互由合法声明定义，不执行作者提供的任意脚本。定义及版本引用不可变，已有对象固定引用；公开字段和固定来源类型不赋予对其他对象或受保护字段的写权限。

模拟使用固定阶段快照与受限效果计划，统一分配真实来源量、目的容量及脏状态，再通过共同提交边界形成结果。事件规则按实际事件顺序处理；本阶段的判断读取固定快照，候选效果按声明顺序结算。本步产物不能被递归立即消费成无限连锁；依赖和独占写入冲突有明确拒绝边界。对象树、批次、活动闭包及序列化大小在接纳时受限。

已保存实例与计算前沿分离。不可变声明推导执行依赖，输入或可见性变化唤醒相关实例；安全可休眠的规则与材料、机械、反馈等保守活动机制分开。邻近事件按真实发生位置分配，消费者队列溢出或缺输入暂停本地处理，不能补造已错过事实或阻塞全部公共历史。

世界逻辑轮由持久协调状态推进。实际容器、机械、可变来源、共享有限资源与传播关系形成相互作用域；同区块、共同定义或审计目录不自动形成计算耦合。各域可分批结算，候选前冻结拓扑与事件截止，未完成域的相关输入受限。观察明确公共目标轮与本域完成轮，不能把分批计算表现为同时完成。

逻辑候选按域隔离，有限后台批次可共享一次物理持久提交。规则或容量失败回滚该域候选；存储故障可能回滚尚未持久确认的整个批次或使结果未知，因此持久提交前不能对外确认成功。已知容量压力等待真实输入变化，不能盲目循环重试。检查点历史可有界回收；当前状态、玩家 Receipt 与仍引用的事实保留，历史缺口显式报告。

机械冻结网络快照后统一求解位置、方向、扭矩、有限能量、负载和行程。循环、多源、过载或能量耗尽停止时保留真实位置，不制造新能量；机械位置由 solver 独占。声明只读机械与事件状态并改变获准字段，不能写受保护身份、普通位置和安全字段。该模型不宣称惯性、重力或碰撞应力。

公共事件先形成持久事实。记录器启用后才按半径与逻辑窗口记录，发生、被记录和由某主体读取是独立事实。世界合同固定条款，由实际主体接受，按真实材料交付、事件与期限结算完成、失败和释放；托管材料不被其他规则消费，沉默不产生同意。这些机制复用状态、Operation／Receipt 和事件，不新增通用审批内核。

声明越界形成该实例的过程错误，不停止整个世界。机械已求解后的声明失败只回滚该实例声明字段与材料变化，保留该轮已形成的机械结果；不能宣称所有程序错误都整网回滚。修复通过合法动作或新版本实例，不改写已发表版本。

物理、记录窗口与世界期限按逻辑时间推进，停机暂停、重启接续。连接超时和机会租约属于运维墙钟；不按每个物理步调用模型。统一轮屏障、单写者存储、高度连通域、身份与空间限额、真实内容增长仍限制规模，分域本身不证明大规模容量。

## 依赖方向

- 世界内核依赖共享合同与内部能力，不能依赖 transport adapter、宿主、renderer、具体 World Package 或测试项目。
- 可移植 World Package 依赖公开作者边界，不依赖内核私有对象、宿主或 UI。
- Agent 交互客户端依赖公开合同与传输抽象，不依赖某个模型、原生会话、人类 DTO 或数据库。
- 宿主 adapter 依赖可复用客户端和具体宿主能力；共享客户端不反向依赖 adapter。
- 人类交互 API 复用世界授权、查询与动作边界；renderer 只依赖其公开合同，不解释内核私有状态或作者程序。
- composition root 可以依赖多个组件，因为它负责组装。

静态依赖检查只能说明它实际覆盖的反向引用，不能成为动态代码隔离或恶意插件安全证据。

## 事务、读取与恢复

Runtime 管理的 Command 写入汇聚到唯一权威事务边界。普通行动与定时效果复用提交语义，使同一提交中的状态、Receipt、事件、通知和后续定时事项一起成立或一起失败。

多进程或 worker 的写入通过存储与 fencing 协调，重复 Operation、过期租约和并发 timer 不能形成两套权威结果。外部副作用处在内部事务之外；确需跨系统一致性时采用明确幂等、outbox、交付或补偿边界。

Query 与 View 使用一致读取快照。派生缓存可重建，不成为提交前提；返回或保存投影检查点前重新校验当前身份、代码与授权。并发变化不拼入旧快照，撤权或代码替换使结果失效。不同消费者均须执行身份、世界、合同版本及顺序校验。

未知传输结果保留原 Operation 与原参数，先恢复持久 Receipt，必要时重试原操作。表现播放、缓存刷新、私人任务停止和连接消失都不能撤销已提交事实。

## 信任边界

客户端、Agent 输出、自然语言、选择器与资源引用均是不可信输入，经 schema、身份、授权和大小边界处理。其他人的内容作为数据交付，不因进入模型上下文就成为控制指令。

用户身份私钥保留在密钥保管端。世界接收公钥与新鲜证明，保存本地身份映射并签发本世界凭据。调用凭据是秘密材料，由宿主或客户端的鉴权层管理；世界规则只需已解析主体与访问模式，不把秘密复制到业务状态或模型文本。

被加载的 World Package 是部署方信任的代码。World Instance 业务隔离不是敌对租户沙箱；有界声明解释器也不等于任意第三方代码沙箱。未来若执行互不信任的世界代码，需要独立进程、权限、存储或真正沙箱，不能用 scope 或存储授权器宣称已经完成。

拥有进程、存储文件、备份或主机管理权限的一方在应用授权之外。应用规则不防止主机管理员读取或修改底层数据。

## 架构变更判断

责任、信任域、提交边界、依赖方向或隔离模型变化才是 L5 变化；文件拆分与重命名不自动构成架构进步。新的服务、消息总线或常驻编排依据真实瓶颈引入，不因 reference adapter 或参考项目采用某种部署形式就复制。
