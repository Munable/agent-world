# 横轴：交互与表现

复核：2026-10-05。本文约束客户端怎样 **忠实表达已经成立的世界事实**。表现不是 L7，也不拥有独立业务权威。

## 当前参与路径与目标颗粒度

当前选择两条并行路径：用户可以在网页直接选择该世界的合法行动，也可以在自己的 AI 工具中下达目标和讨论计划，由工具调用同一接口。网页展示当前场景、行动风险、获准状态、后果与接续记录；不转发目标、不启动或暂停外部推理，也不承担 WASD、采集、种植等动作游戏系统。官方地城的选择按钮是 World Package 行动的消费者，不能自行创造结果。

目标颗粒度是使用指导，不是新的领域对象或 Runtime 合同：

| 用户表达 | 用户与工具如何处理 | 世界提供什么 |
| --- | --- | --- |
| 长期方向，例如“从 1 级升到 60 级” | 保留长期目的，先确认策略与执行边界，按可以检查结果的阶段持续推进。阶段不要求逐次人工批准；出现新选择、超出授权或无法判断时再讨论。 | 若该世界定义了等级等机制，提供其规则与当前事实；不承诺工具能无限运行或替用户规划路线。 |
| 当前任务，例如“按上次经验采购地下城补给” | 用本地经验结合当前世界事实，确认预算和必要偏好，执行后读回结果。任务短也可能存在重要选择。 | 若该世界定义了商店与物品，提供当前库存、价格、合法交易及可核对的结果；不推测用户的私人经验。 |

区分两者不能只看预计用时或指令长度；更关键的是完成条件是否可观察、信息是否充分、是否会遇到新的决策，以及成本和后果是否超出用户授权。用户工具可以自主拆解和执行，不要求用户逐项指定底层动作。世界也不因为收到宽泛目标就推断一个统一规划流程。

世界使用说明应让用户和工具找到：如何接入、能采取哪些行动、已有规则中的前置条件和代价、结果到哪里核对、失败后怎样继续，以及退出或离线时世界中哪些过程仍会发生。用长期方向和当前任务的示例说明如何设置执行边界；这些内容随具体世界而定，不要求所有世界拥有等级、背包、商店或截止时间。

可以要求用户掌握接入方式、阅读世界入门说明，并向自己的工具说明必要偏好与边界；工具与用户负责保留私人目标和本地上下文。长目标无需禁止，也无需承诺一句话后无人照看就必然完成。重新开始时，工具结合迁移的私人上下文读取最新世界状态与未知操作结果，而不是仅按旧计划重复执行。

网页展示世界实际记录的进展，不从私人目标推算统一完成百分比，也不把近期没有动作显示成 Agent 已停止。只有具体世界已经定义并保存的完成条件才能作为世界完成事实显示；连接授权、离开页面、撤销凭据和停止本地推理仍是不同操作。

## 语义边界

- 文案、动画、缓存、音效、模型总结和本地队列都不能创造服务器没有形成的业务事实。
- “已发送、已投递、已读、已回应、已确认、已执行、已完成”必须对应真实领域语义；为了界面简洁不能把不同状态合成一个会误导用户的标记。
- 客户端发现模型／合同难以理解时可以反馈到 L3/L4，但在上层正式修改前不能自己发明新业务含义。
- 服务器返回的自然语言、资源引用和表现参数都是数据，不应因为出现在表现层就自动变成 HTML、代码或控制指令。

## 表现信号

Runtime 可以随着一个已提交世界动作发出用于表现的信号，例如动作开始／结束、发言或公开意图。表现信号只描述已经由世界规则产生的逻辑事实，不是另一套控制平面。

表现信号的受众必须由世界规则或已有可见性决定；名字叫 speech、intent 或 action 不能自动扩大可见范围。公开意图也必须是主体明确提交的数据，而不是 Runtime 推测私人思考。

表现信号可以与产生它的世界提交原子记录，但动画播放完成不能触发第二次隐式业务提交。

## 恢复与乱序

表现队列可以丢失、过期或被缓存驱逐；重要的进行中业务必须能从授权 View／State 恢复，而不是依赖某段动画仍在内存。

客户端必须去重重复表现信号，并拒绝把旧异步响应覆盖到新世界快照上。刷新页面、清空缓存或取消动画都不能改变服务器业务结果。

历史表现记录与现场表现必须区分；恢复旧历史时不应把已经发生过的奖励、伤害或动作再次播放成新的世界效果。

## 客户端验收关注点

1. 重放／重复读取不会制造第二次业务动作。
2. 乱序更新不会回滚客户端对当前世界的理解。
3. 权限撤回后不继续使用受保护缓存获取新数据。
4. 表现丢失后仍能从权威状态恢复业务。
5. 确认、完成、失败等用词与 L4 世界语义一致，而不是从网络状态或文本内容猜测。

具体 Presentation 类型、timeline/View 绑定、channel/phase、客户端 helper 和当前限制见 [IMPLEMENTATION](IMPLEMENTATION.md)。美术、相机、寻路和领域动画本身不是 Runtime 通用验收门槛。

## EigenFlux 参考建议

接入界面／宿主状态应分别表达“已安装／适配存在、身份已建立、权限当前可用、持续运行已授权或不可用”，不能把安装成功显示成 Agent 已在线。错误提示优先呈现安全的下一步动作，例如重新授权、等待后重试、恢复 Receipt 或重置 Snapshot，而不是把所有失败压成一句“请求失败”。

Reference Application 的通知、会话和未决事项要忠实表达服务器事实：等待不等于拒绝，通知读过不等于接受，不保证投递的操作不能显示成对方已读。名称与文案帮助人理解事实，但不能制造认证、关系或完成状态。
