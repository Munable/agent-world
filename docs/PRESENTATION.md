# 横轴：交互与表现

复核：2026-09-27。本文约束 **客户端如何忠实表达已经存在的领域和服务端事实**。它不是第七层，也不定义世界业务状态机。

## 基本边界

- UI 文案、动画、缓存、模型总结、读取进度和本地队列不能创造服务器没有提交的业务事实。
- “已发送”“已投递”“已读取”“已回应”“已确认”“已执行”“已完成”必须按世界真实对象与行为合同分别表达，不能因为视觉简洁合并成一个绿色勾。
- 客户端可以发现 L3/L4 设计难以理解并向上反馈，但在设计修改正式发生前，不能用 UI 自己发明新语义。
- 自然语言展示仍是数据；renderer 不应把返回文本当 HTML、代码或 Runtime 控制指令执行。

## Presentation Cue

PresentationCue(cue_id, subject_id, channel, phase, name, data) 生成普通表现事件，当前信封类型为 world.presentation。

它按角色投递时只对该角色可见；只有显式发布到获准共享频道时才遵循该频道可见性。名字叫 speech、intent 或 action 不会自动扩大公开范围。

当前 channel 为 action / speech / intent，phase 为 start / finish / cancel。cue_id 关联表现生命周期；subject_id 指向世界对象；name/data 由世界规则定义。intent 只能表示明确提交的意图数据，不是服务器推测的私人思考。

Runtime 校验信封与大小，并可使其与状态和回执原子提交。世界仍负责主体、受众、生命周期及 payload 的领域合法性；表现信封不实现移动、对话、审批或确认状态机。

## Timeline 与客户端队列

ViewSpec(timeline=True) 返回独立 timeline cursor。timeline 读取仍需复核当前视图权限，只返回原接收者且主体仍可见的 cue；受众由世界规则决定，不由 renderer 推断。

检查点与 timeline 缓存可以过期、驱逐或因版本变化要求 reset。重取快照时客户端应取消不再适用的表现队列，而不是补造已经清理的动画历史。

表现数据描述逻辑动作，不应持续写入渲染帧。当前仍在进行的业务状态必须能够从获准 state/view 恢复；动画结束不触发第二次隐式业务提交，表现队列丢失也不改变结果。

## 客户端验收

使用表现事件的客户端至少检查：

1. 同一 cue 的重放／重复读取不会产生重复业务动作。
2. 乱序网络响应不会把旧视觉状态覆盖到新快照。
3. 权限撤回后不继续使用受保护缓存。
4. 页面刷新、缓存清空或动画丢失后，业务状态仍从服务端事实恢复。
5. 对确认、完成、失败等词语的展示与 L4 合同一致，而不是根据 HTTP 状态或文本内容猜测。

美术、相机、寻路、行走帧和领域动画由世界／客户端实现，不进入 Runtime 的必要验收范围。具体测试证据见 [REFERENCE_GATE](REFERENCE_GATE.md)。
