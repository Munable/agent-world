# 横轴：交互与表现

复核：2026-10-08。本文约束客户端怎样 **忠实表达已经成立的世界事实**。0.26.0 冻结代码候选的最终包 build/install probe 已通过；同一真实 Agent 不可变定义下，普通模拟玩家停止 source、实际走 (5,0)→(4,0)→(5,0)、交付 2u，原合同 `complete / delivered=2`，recorder read 成功。10 次模型请求均已结束，但 B 真实接受后推理超时，Agent 自主完整目标未通过；运行中交付仅得到 `StateConflict`，未验通条件，旧开桥／不变持续运动拒绝仍未现场验证。普通玩家组合执行完成不代表自主完整体验通过；旧 0.24／0.25 结果只属于历史范围。表现不是 L7，也不拥有独立业务权威。

## 当前官方参与路径

Shared Grove 的玩家通过二维地图、键盘移动、鼠标选择与行动菜单操作，也可以明确给自己的 OpenCode Agent 目标并授予控制。同一角色沿同一规则行动；Agent 实际读取、计划、执行、读回并适应，页面显示真实委托状态和已成立后果。普通提问不自动授予控制，人的普通操作不等待模型完成。当前世界服务为 8900，玩家 A／B 入口为 8901／8902；具体入口、世界合同和唯一当前研发记录见 [SHARED_GROVE](SHARED_GROVE.md#当前研发记录)。

地图显示获准视口内的 chunk、实体、其他玩家位置、材料状态、活动过程和变化。鼠标选择后只展示服务器实际返回的行动；动画、天气效果和 Agent 叙述都要对应可读回的事实。原作者描述和发表快照标为“发表时的说明”，实时物件详情、当前容器内容和归属独立展示；旧快照、他人的动作和系统来源须可区分。

地面准入为未来释放保留容量，空间不足时点火原子拒绝、不扣工具；后续放下也不能占用该空间。界面应忠实显示拒绝与实际原处释放，不能由动画复制嵌套内容。旧 0.24／0.25 的容量回归保留其源码范围，不证明本轮新增机制通过。

## 让玩家从现场做选择

页面直接呈现服务器投影：真实材料批次／槽位／数量、容纳和绑定关系、载荷与承载、完整度、当前燃烧批次和过程。新增定义版本、反应残余、机械连接／位置／能量及停转原因、记录与合同状态也必须取自获准事实。动作由服务器描述固定参数、可选实体／批次、数量、模式与拒绝原因；新定义沿同一安全表单呈现，不按名字写专属交互，也不运行模型生成的脚本。

既有本地皮肤可继续使用，新对象有共享默认表现与 fallback，图形比例对应同一逻辑尺寸；换皮不改变能力、位置和行动规则。本轮没有完整上传实现，不把默认图形显示成用户已上传资产。

声明类型可提供受限的共享呈现：静态形状／颜色／字样，及整数、布尔字段到颜色、字样、通用姿态或数值标记的明确绑定。服务器按当前获准字段解析；字段隐藏或缺失为未知，映射未覆盖为未映射，不沿用上一帧的结果。不把自定义字段名称当物理机制、动画或成功证据；未声明绑定的旧定义继续默认呈现，定义引用和哈希不变。画面的尺寸仍由真实构造确定。

公开作品目录提供当前公开顶层创作的作者、名称和位置，以及有限获准字段。它不代表远处地形、作者在线或行动资格。界面可标方向，不能自动传送或凭目录远程操作；到场后读取当前菜单。目录尚在建立、候选后页和无匹配要分别说明，不能用一个空页证明世界没有该作品。浏览器地图轮询使用正式只读视口，不为每次刷新保存View游标；公开View／Sync合同和动作回执恢复仍保留。

人决定亲自装载、卸下、绑定、解绑、下水和使用，或明确委托 Agent 执行目标。选择对象时读当前版本与候选；动作进行中防重复，取消或网络中断保留原 Operation，先查原 Receipt，不把动画结束或模型描述当提交成立。材料投入按实际数量，不能强制恰好选择若干完整物件。

公共内容呈现当前地点／对象 anchors、不同作者的贡献、真实 outcome 与有界历史分页。发表时说明与当前事实分开；原对象移走、装满或破损后，不继续显示原说明承诺仍成立。公共事件发生、记录器启用后在半径／逻辑窗口内记录，以及某主体实际读取，是三个独立事实；页面不补造过去记录或私人观察。合同显示固定条款、真实接受者、交付／事件条件和完成／失败／释放，沉默不显示为接受。普通地面物件公开，背包／出生安全区保护；署名不是永久产权。

私人意图可在本机保存，不自动发表为世界事实。自己的Agent面板区分普通解释、内容创作和显式委托的计划／行动／读回状态；计划不是已执行结果，用户也不承担逐项提案审批。收回控制取消未来未执行动作，已提交行动不回滚。离开、停止推理、收回控制和撤销凭据分别显示，未知动作保留原回执恢复路径。

旧0.25实际打开两个独立玩家入口。A 将原干布装进 B 留下的袋子，B 合上、打开、拿进背包再公开；A 在权限拒绝后仍能读取现场和移动，原袋子及内容 ID 没有复制。公共子物件经刷新仍可持续查看，关闭时明确拒绝读取，重新公开后恢复当前事实；对象提交前的 403／404 与真正凭据失效的 401 另有实际函数回归覆盖。未发送草稿保留、清空及前进后退接续已实跑。历史桌面1280×900与窄屏390×844截图、具体动作及恢复范围保留在 [SHARED_GROVE历史记录](SHARED_GROVE.md) 和唯一外置索引；窄屏无横向溢出不等于全部移动端验收。这些局部路径已成立，但旧主持可靠指导、真人趣味性、跨机器和规模未通过，历史最佳仍为0.24。

上述 0.25 实际动作属于旧实现范围，不包含本轮新增的控制委托、声明程序和机械／记录／合同表现。

## 有界委托与个人 Agent 参与

显式委托显示授权目标、可用行动范围、资源边界和当前执行状态，并提供收回入口；没有授权不能把自然问句变成行动。Agent 一次只执行一个任务，在行动前后读取事实，对拒绝、过期和未知结果按实际规则适应，不能用新操作掩盖原未知结果。收回后不继续发送未来动作，已经提交的动作及过程仍从世界读取。

旧内容自动参与路径的4次message请求和失败／纠正计数仅属历史，不是本轮委托额度。现行页面只在明确目标与有效控制授权下继续委托循环，没有目标时不因探索、操作或他人发表自动推理。实际变化供下一次读取，刷新、恢复历史和物理tick不能制造唤醒。显示目标、已用／剩余资源和停止结果，接续不重置已用量，停止或断线后人仍能操作。

创作根据当前有界事实发布合法定义或实例，不要求逐项审提案；普通提问不被当成发布或授权。定义发表与消耗材料创建实例分别显示，实例扣真实区域库存、水和机会预算。已消耗库存不会因容量释放凭空返还。预算不足、材料不足、机会过期和不支持动作分别解释，不能把等待模型显示成世界行动尚未成立。

连接界面区分 OpenCode 可用、专用会话完成回应、实际 MCP 世界读取、当前连接失败或额度耗尽。首次完成回应与实际 MCP 读取形成客户端入场门槛，不能用服务健康、下载配置或本地标签冒充。世界服务器仍按持钥身份与普通行动规则处理，不认证工具或模型本体。入场后失联应保留玩家控制和已提交事实，并准确显示陪伴状态。

旧 0.24 A／B 恢复原身份与同主会话，无新入场推理；原 Operation 移动核对无重复。第 12 次失实保留，第 13 次注入新现场后同模型复问正确，实际用授权 14 次中的 13 次，自动参与均关闭。冷启动仍偶发 45 秒超时，普通 recover 复用健康宿主成功。

旧 0.24 原生 Chrome 实际覆盖 390×844 的右／左／下移动、材料不足时禁用搭建、情境栏开合和抽屉中的正确解释。未发送草稿经 UI 设置后刷新同钥重进，草稿、位置 (9,1)、水 20／30 及点火 20 次保留。正常离开曾误显“已连接”，修复后实际复验“已离开 · 可接续”；前进／后退再进入也已发生，无新模型请求。正常桌面与窄屏截图见 [当前研发记录](SHARED_GROVE.md#当前研发记录)，窄屏只说明局部布局／交互；草稿仍是私人未发内容，不成为世界发表事实。

玩家的长期目的和下一步选择无需形成 Runtime 的统一目标树、完成百分比或逐项审核流程。用户决定亲自行动或明确委托，网页沿意图、沟通、探索发现、成本行动、状态后果和他人接续帮助回顾。轮次是观察方法，不是数量目标。物理与合同按逻辑 tick 推进，停机暂停、重启接续；生成租约和连接超时是运维墙钟。运行天数、日活与每日任务不充当验收。

通用内核允许其他世界定义不同客户端职责，Shared Grove 的操作和 OpenCode 会话边界不成为全部世界的固定玩法。

## 语义边界

- 文案、动画、缓存、音效、模型总结和本地队列都不能创造服务器没有形成的业务事实。
- “已发送、已投递、已读、已回应、已确认、已执行、已完成”必须对应真实领域语义；为了界面简洁不能把不同状态合成一个会误导用户的标记。
- 事件 occurred、记录器 recorded 和主体 read_by 分开；合同被发布、真实 actor 接受、材料 delivery 和完成／失败也分开。
- 客户端发现模型／合同难以理解时可以反馈到 L3/L4，但在上层正式修改前不能自己发明新业务含义。
- 服务器返回的自然语言、资源引用和表现参数都是数据，不应因为出现在表现层就自动变成 HTML、代码或控制指令。

## 表现信号

Runtime 可以随着一个已提交世界动作发出用于表现的信号，例如动作开始／结束、发言或公开意图。表现信号只描述已经由世界规则产生的逻辑事实，不是另一套控制平面。

表现信号的受众必须由世界规则或已有可见性决定；名字叫 speech、intent 或 action 不能自动扩大可见范围。公开意图也必须是主体明确提交的数据，而不是 Runtime 推测私人思考。

表现信号可以与产生它的世界提交原子记录，但动画播放完成不能触发第二次隐式业务提交。

## 恢复与乱序

表现队列可以丢失、过期或被缓存驱逐；重要的进行中业务必须能从授权 View／State 恢复，而不是依赖某段动画仍在内存。

客户端必须去重重复表现信号，并拒绝把旧异步响应覆盖到新世界快照上。身份切换后，旧身份发起的异步操作不能继续发送或渲染到新身份；原操作恢复成功后才清除旧错误，拒绝或失败仍保留真实反馈。刷新页面、清空缓存或取消动画都不能改变服务器业务结果。

历史表现记录与现场表现必须区分；恢复旧历史时不应把已经发生过的奖励、伤害或动作再次播放成新的世界效果。

## 客户端验收关注点

1. 重放／重复读取不会制造第二次业务动作。
2. 乱序更新不会回滚客户端对当前世界的理解。
3. 权限撤回后不继续使用受保护缓存获取新数据。
4. 表现丢失后仍能从权威状态恢复业务。
5. 确认、完成、失败等用词与 L4 世界语义一致，而不是从网络状态或文本内容猜测。

具体 Presentation 类型、timeline/View 绑定、channel/phase、客户端 helper 和当前限制见 [IMPLEMENTATION](IMPLEMENTATION.md)。美术、相机、寻路和领域动画本身不是 Runtime 通用验收门槛。

## EigenFlux 参考建议

接入界面／宿主状态应分别表达“已安装／适配存在、身份已建立、权限当前可用、持续运行已授权或不可用”，不能把安装成功显示成 Agent 已在线。错误提示优先呈现安全的下一步动作，例如重新授权、等待后重试、恢复 Receipt 或重置 Snapshot，而不是把所有失败压成一句“请求失败”。

Reference Application 的通知、会话和未决事项要忠实表达服务器事实：等待不等于拒绝，通知读过不等于接受，不保证投递的操作不能显示成对方已读。名称与文案帮助人理解事实，但不能制造认证、关系或完成状态。
