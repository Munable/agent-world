# 旧灯塔：第五版规则本地试玩

## 玩家入口与维护资料

第一次玩请读独立的 [试玩指南](DND_PLAY.md) 和运行中世界手册。本文面向维护者，包含场景设计、对象分布和验收资料，不能作为人物取得未探索秘密的来源。玩家入口单独保存，避免要求新玩家在同一长文中自行区分试玩指引与维护内容。

## 体验与边界

这是基于 2014 第五版、SRD 5.1 的一级角色小地城，用来同时体验规则说明、探索、技能、谈判、战斗、多人变化和离开后的接续。本地实例最多 16 个人物、160 条自由意图，属于有限试玩容量，不代表 MMO 规模。场景是原创内容，不搬运商业冒险全文，不宣称完整实现 D&D。

人物可以接受管理员的寻物请求，也可以调查、赠与、谈判、帮助别人、保留发现或观看。任务不是协议规定的用户目的。网页和外部 AI 工具使用同一身份与世界动作；游戏属于示例世界，内核不新增冒险者或 Agent 身份。

玩家会看到一处共享的旧灯塔：其他人已经打开的门仍然打开、拿走的物件不再原地出现、受伤的占据者不会因为新玩家进入而刷新。唯一的铜质航标印可以被取得、转交或交还守灯人，其归属保持连续；没有放下或刷新物件的动作。

## 场景交互与失败

- 普通查看、读取已可见内容、拿取无人持有且能接触的物件、合法转交不需要掷骰。`search` 只在储物间实现，其他房间由 `look` 描述；搜查不会在每个地点任意生成线索。所有权变化由服务器提交。
- 门厅锁门可用盗贼工具进行 DEX 检定（DC12），也可 STR (Athletics) 破门（DC15）。失败不凭空消耗装备；撞门会留下可见声响。未变化情况下反复用同一方法不能靠不断新请求重掷直到成功。
- 携带绳索在回廊设好安全路线后可以通过；绳索转为通路设施，不能同时留在背包或再次转交。单独跳过缺口按 STR (Athletics) DC12，失败跌落 10 英尺，伤害 1d6，留在回廊。成功和失败都形成正式结果。
- 占据者接受通行谈判，基础 CHA (Persuasion) DC13；持有实际 `ledger_page` 时可用 `option: ledger`，难度 DC10。成功只产生通行与停止阻拦的有限许可，不等于操控他们全部意愿。不能裁决另一位玩家自动交物。
- 占据者采用 SRD Bandit 的 AC12、HP11、弯刀 +3 / 1d6+1；当前不实现轻弩。先攻与战斗结果由规则执行，不能由叙述宣布死亡。
- 治疗药水恢复 2d4+2 HP，使用后不可再次使用。短休花费有限 Hit Die；战士 Second Wind 的次数由状态记录。
- 归还航标印需要本人实际携带并位于营地；成功后从背包移除，世界记录 `seal_returned / returned_by / returned_at`，不发放或重复发放虚构 XP、金币。转交是赠与，不替接收者接受寻物任务；本轮没有双向交易合同。
- 未支持的机制明确返回未支持或需要规则解释，不能捏造“已经失败”的游戏结果。离开或换工具不恢复药水、HP、职业次数、门、NPC 或唯一物件。

这些 DC、对象、NPC 动机与通路属于原创场景设定，不是声称 SRD 为每扇门固定了这个数值。

## 规则分类

SRD 核心：属性修正、熟练、d20 检定、优势/劣势、攻击与暴击、先攻、有限职业能力、HP、恢复与 0 HP 流程。技能检定自然 1/20 不自动失败/成功；攻击自然 1 必失、自然 20 必中并增加伤害骰，固定修正不翻倍。角色卡列出实际技能修正；自由裁决当前只支持基础属性检定，不自动加入技能熟练。

场景适配：房间位置、路线条件、有限对象效果、NPC 谈判条件与战斗策略。采用近距 theatre-of-mind：同房间的近战距离被抽象；同一战斗中存活伙伴可满足本切片的邻接盟友条件，不宣称精确站位。参加别人的战斗需要明确 `join_combat`，路过房间不会自动被拉入。两个 Bandit 使用各自先攻，NPC 回合由有限代码策略执行，优先攻击最低 HP 的存活参战者，不攻击旁观者；不能靠其他人的调用跳过一位玩家的回合。

首次 `attack` 或 `join_combat` 建立战斗及先攻，结算排在前面的 NPC 回合，不在先攻之外免费攻击。进入自己的合法回合后，再用 `attack` 执行攻击。中途加入者记录先攻，本轮末取得首次回合，下轮再按先攻排序；这是本世界的加入规则。普通战斗动作完成并结束自己的回合；Second Wind 是附赠动作，不结束该回合。`dodge` 给后续敌方攻击劣势，当前没有额外敏捷豁免场景。`retreat` 用整回合退到门厅，无借机攻击；再次参战要明确加入。旁观者不能无限免费帮助或给战斗中的角色治疗。

游戏时间、回合与真实时间不同；在动作推动的世界里休息或经过一个回合，不构成真实经过一小时或跨日运行的证据。离线角色的战斗回合可能等待本人恢复后行动或撤退；服务器不会擅自代理玩家，其他区域仍可继续活动。

未支持：完整战棋、全部光照与负重、复杂旅行、所有反应和机会攻击、非致命击昏选项、PvP、全法术、全职业、升级、无限地图生成、后台推理。NPC 的 0 HP 表示击败，不能从当前字段推断出未实现的俘虏或击昏状态。具体动作以 `dnd.look` 返回的当前目录和角色状态为准；文档不能使后端尚未实现的动作变得可用。

## 0 HP 与休息

- 活着且 HP 为正才能正常行动。0 HP 不稳定角色使用 `death_save`：10 及以上记一次成功，低于 10 记一次失败；自然 1 记两次失败，自然 20 恢复 1 HP。三次成功稳定，三次失败死亡。
- 附近清醒角色可用 `stabilize` 与 `recipient` 作 WIS (Medicine) DC10 急救，成功稳定但不恢复 HP。实际药水可以治疗稳定或不稳定伤者，不能复活死者。稳定角色在战斗中跳过回合。
- `rest`、`option: recover` 只供非活跃战斗中的稳定 0 HP 角色：服务器掷 1d4，推进其个人故事小时并恢复 1 HP。它没有让现实等待该时长，也不等于短休或复活。
- `rest`、`option: short` 在营地或储物间供存活角色使用：推进一故事小时；受伤且有生命骰时消耗一枚、掷对应职业生命骰加 CON 修正，恢复至多最大 HP；刷新 Second Wind。0 HP 不能通过短休复活。
- `rest`、`option: long` 只在营地供存活角色使用：必要时自动推进个人故事时钟，满足距上次长休开始至少 24 小时，再推进八小时休息，恢复 HP、一级角色的一枚生命骰和 Second Wind。这个可跳过等待的个人叙事时钟是本地切片适配，不是全世界同步时间或自然跨日测试。

## API 与 JSON 约定

这些都是示例世界函数，使用现有 Runtime 的 HTTP/MCP 调用、Operation、权限和 Receipt；不增加 transport 专用游戏逻辑。

| 函数 | 语义与参数方向 |
| --- | --- |
| `dnd.join` | 创建或恢复本主体角色；预设职业只在首次创建时选择，重复进入不能刷新状态 |
| `dnd.look` | 读取当前角色、房间、合法目标、变化、动作；只返回授权可见事实 |
| `dnd.handbook` | 按 `chapter` 读章节；`gm` 后端检验裁决者权限 |
| `dnd.act` | 目录内动作，由 `action` 指定；目标、地点、接收者按该动作实际 schema 提交 |
| `dnd.propose` | 规则不能直接覆盖的办法；说明方法、目标和希望产生的效果，不直接改变目标 |
| `dnd.rule` | 获准裁决者给出有界条件、检定、消耗、风险与允许后果，不能任意改状态 |
| `dnd.commit` | 提交者承诺当前有效裁决的风险；服务器掷骰并一次性提交后果 |
| `dnd.withdraw` | 提交者撤回尚未承诺执行的意图，不能撤销已看到的失败结果 |
| `dnd.say` | 发表可归因的发言；发言不能替别人作出授权或改变事实 |
| `dnd.history` | 授权历史与分页接续；结果与他人的断言分开 |

当前函数参数示例（不含 Runtime 外层鉴权及 Operation envelope）：

```json
{"name":"来访者","class_id":"fighter"}
```

这是 `dnd.join` 的参数；`class_id` 可选 `fighter / rogue`，重复调用恢复已有角色，不改变职业。获准裁决者可以不创建角色就读取 `look / handbook / history` 的授权观察投影，`character` 为 `null`。

```json
{"action":"move","target":"entry","expected_character_version":1,"expected_scene_version":1}
```

这是 `dnd.act` 的参数形状；版本必须取自刚读到的 `look`，示例中的 1 不能照抄用于已变化的世界。完整允许字段为 `action / target / recipient / option / expected_character_version / expected_scene_version`。`heal` 的 `option` 是 `potion / second_wind`，药水接收者默认自己，`second_wind` 仅限战士自身；`rest` 的选项为 `short / long / recover`；`negotiate` 可省略选项或使用 `ledger`。

动作参数使用真实返回的 JSON Schema，不能从自然语言说明猜出一个任意函数或效果。所有写动作带稳定 Operation ID；相同 Operation 重试读取原回执，不重掷骰、不重复消耗。并发拿取同一共享物只有一个合法结果；旧对象条件冲突时读最新状态再决定。

`dnd.act` 的目录：

| `action` | 作用 |
| --- | --- |
| `move` | 沿允许路线改变房间 |
| `search` | 搜查当前场景并发现可见线索/对象 |
| `unlock / force` | 用工具开锁或破门，按对应条件检定 |
| `set_rope / jump` | 建立绳索通路或承担跳跃风险 |
| `negotiate` | 尝试有限通行谈判 |
| `take / transfer / deliver` | 拿取、转交或按场景条件交付物件 |
| `attack / join_combat` | 发起攻击或主动加入当前战斗 |
| `dodge / help / end_turn / retreat` | 闪避、帮助、结束自己的回合或撤退 |
| `heal / rest` | 使用符合条件的恢复方式 |
| `stabilize / death_save` | 按当前 0 HP 状态施救或死亡豁免 |

`target` 指向房间、物件或 NPC；给另一角色使用 `recipient`。`option` 等附加参数按动作返回的真实 schema 使用。自由输入可以映射这个目录，不能写成一个未实现的 `rig_rope` 或 `short_rest` 函数。

## 自由办法的承诺顺序

1. 玩家表达意图；已有规则能完成的直接映射目录动作。
2. 需要解释时，获准裁决者引用当前事实，选择基础属性检定、DC10–18、可选优势和允许的成功/失败效果；消耗由对应有限效果决定，不能任意加字段。
3. 玩家看到风险，选择承诺或撤回。
4. 承诺时再次检查角色、目标、资源和裁决仍有效；服务器掷骰、执行、保存回执。
5. 叙述解释已提交的结果。承诺之后不能通过取消、断线或新模型重选骰子。

裁决者不能改写已有秘密、替其他玩家同意、复制唯一物或建立新机制。外部裁决工具离线时，该意图显示等待；不会伪装成世界正在自动思考。其他已有动作继续可用。 自由文本的同义改写不能由无推理服务器自动识别；相同已知动作与已记录检定条件受代码约束，自由方法是否只是换句话重试由获准裁决者按当前事实判断。不能把这个边界说成语义防刷已自动解决。

当前有限成功效果是 `open_bandit_door / secure_gap / bandits_allow_passage / reveal_store / none`；失败效果是 `none / damage_1d6`。它们只可用于存在对应目标与条件的场景，不能拿 `open_bandit_door` 打开任意城堡。对象条件改变使裁决过期后，需要根据新事实重新裁决，不能沿用旧结果。

`propose` 必须带 `intent_id / text / expected_character_version / expected_scene_version`。每个角色最多一个未决提议，自由裁决只在非战斗状态使用。

`rule` 参数为 `intent_id / ability / dc / advantage? / success_effect / failure_effect / reason / risk`，`ability` 是 `strength / dexterity / constitution / intelligence / wisdom / charisma`。报价成为 `offered` 后裁决者不能覆盖；本人可以撤回并另提。`reason / risk` 为公开说明，不放私密内容。

后端返回的 `terms / server_terms` 明确实际检定、固定物件消耗、伤害和失败后不能重刷的约束，优先于裁决者的文字说法。`secure_gap` 成功必须消耗实际携带的唯一绳索；不能通过描述虚构材料。不同文案、降低 DC 或换 Operation 不形成新方法；该切片按场景、效果、属性及实际证据记录失败条件。裁决者授权代际、本人位置／资源／伤情或实际房间条件变化会阻止旧报价提交；别人仅离开房间或休息不会改动该门的条件。房间版本只随房间内容改变，本人的角色版本另行保护其自身条件。

裁决者可以依据 `look` 的真实场景描述、对象状态、角色装备和普通物理知识判断方法是否值得尝试。无需先为所有杠杆、卡点、支点建立属性或调查动作。对象、材料、位置、权限等关键条件仍须成立；力度、手法、是否滑脱等一般不确定可以由检定处理。推断须在报价理由中解释，不能把未确认的秘密或未来结果宣布成事实。

本切片没有装备耐久和损坏系统。若有限效果能表达办法的主要成功与失败结果，裁决者可在现有开门、失败无变化或伤害等范围内报价，公开说明不结算装备损坏，不为了非核心细节要求新增机制。若缺少机制会使核心风险无法表达或办法根本无法成立，应明确指出原因与现有可行下一步。不能硬给成功，也不能要求调用不存在的调查接口；当前 `search` 仅用于储物间，其他场景已知构件从 `look` 读取。

## 本轮验收

功能完整后统一执行确定性规则与协议测试、网页操作以及少量有调用边界的真实 OpenCode/Codex 运行。覆盖两职业、两路线、谈判/战斗、有限自由裁决、同物并发、同身份多工具、幂等、断线、新会话、重启与备份恢复。网页检查正常、失败、取消、重复点击、前进后退与窄屏。

真实模型必须根据公开说明取得事实、调用动作、读取结果，并在新进程接续；提示词里直接告诉它“你成功了”不算完成。测试报告区分实际执行、模拟和未验证。真人趣味性、自然跨日与长期可持续性不能由脚本数或一次短模型会话代替。

## 四玩家与各自助手的说明书复玩

本次检验的假设是：助手能从公开手册把现场转换成玩家可判断的选择，围绕各人的目的推进一段，并让后来者理解和回应其他人留下的实际变化。模型扮演玩家，不能验证真人是否好玩。使用四个独立本地 Codex 玩家线程；每位玩家自己创建一个 GPT‑6 Luna／medium 助手线程，模型与档位从这八个线程的实际运行记录核对。四个助手只用各自身份的临时 HTTP 适配器，传输脚手架没有游戏策略；本次不是新增 MCP 实测。

岚灯选择社交和安全观察；雾岬选择核对故事线索；听潮选择尝试自己的撬门方法；林澈后来进入，选择与现有人物交流，未默认接受寻物任务。前三位经历旧手册与修订手册两个阶段，林澈从修订说明开始。这不是严格控制变量的手册效果对比。

实际结果：

- 岚灯公开介绍自己、追问另一人的说法来源，再到门厅观察，未加入别人的提议或战斗。
- 雾岬回应听潮后仍坚持自己的调查方向，搜查储物间并发现账页，起初未拿取。林澈到达后，雾岬恢复并分享线索、询问他的门厅观察，没有承诺同行。
- 听潮独立提出短剑杠杆办法。组织者以获准外部裁决者身份给过两份有限报价；第一份因旧代码把别人的离房算成房间变化而过期。本人撤回、重新提案并接受第二份：服务器实际掷出6−1=5，未达到DC15；伤害2，HP从10降至8，门仍锁着，没有第三次刷骰。在两次重启检查中，原Operation重放仍返回原结果。
- 林澈读懂听潮此前失败和受伤的公开记录，来到储物间向雾岬询问。收到雾岬的真实回应后，他取走唯一账页并分享门厅观察及账册记载；背包持有账页，原处没有第二份。未转交、接任务或参战，雾岬尚未再次回复。

四个助手共120次有回执的HTTP请求、25次写请求；另有组织者13次HTTP检查／报价／原Operation重放，以及1次服务未就绪的只读启动探针失败。适配器硬上限为A/B/C各60次、D30次，所有角色均未达到上限；全部八个线程已停止活动。Codex使用既有订阅，没有新建凭据路线、充值或修改地区／隐私设置；记录Token用量，不从缓存Token或订阅额度推断实际账单。

本次发现并修复L6缺陷：别人的移动或休息不应让仍未变化的门锁报价过期。保留旧源码下失败的复现和最终代码回归，实际房间改变与本人位置／资源变化仍由各自版本保护。公开手册增设`play / agent / together`，接口与世界合同版本升至2，状态版本仍为1；真实重启保留原角色、物件及结果，没有重新初始化。最终450项Python回归、19项定向回归、相关Node客户端及实际wheel安装检查通过；新增手册在浏览器实际读到，375px布局无横向溢出，同钥网页接续仍为岚灯。后续纯说明文字及玩家入口拆分另做内容／链接／差异检查，不计成新增功能测试。

失败和限制也保留：雾岬首次未入场便`look`得到403，随后按规则加入；现在入口明确顺序。岚灯的模拟玩家总结误称当前投影未显示待决提案，而助手实际读到了报价。听潮把本次组织者报价预算误说成游戏只准两次报价，现已在助手章节明确区分宿主预算与世界规则。林澈的模拟玩家首次读到了要求以外的维护资料，后续从同一长文划出独立[DND_PLAY](DND_PLAY.md)入口；其追加复查用了两个助手回合、9次请求，超过该段要求的一轮／6次软预算，但未超过30次硬预算。这些偏差不能写成干净的盲测通过。

判断：目前能由不同目标的玩家解释、选择、交流、改变共享物件并接续失败；尚不能据此说“多人很好玩”。这一轮没有实际多角色共同战斗、Help或赠与流程，相关代码回归不代替玩家体验。场景线索、NPC互动与后续内容仍少；自由办法的两份报价由组织者有限响应，不证明裁决者持续在线或服务器托管推理。单轮助手实际处理通常几十秒至几分钟，包含手册读取、模型处理及等待；真人趣味、自然跨日、长期活动和规模仍未验证。

当前复玩证据集中在`/Volumes/DevDisk/DeveloperData/agent-world/evidence/dnd/players/`：`acceptance.json`记录边界、结果与来源，`dialogues.json`保存双方可见交流，`public-requests.json`保存真实调用和回执。最终日志、旧代码复现及真实截图保留；重复中间日志／已收录的分段请求副本清理。试玩数据库、适配器和私密身份在原外置位置保留，8798／8800本机预览继续可用；未改生产、未推送或部署。
