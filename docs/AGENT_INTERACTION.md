# 外部 Agent 接入与交互

文档复核：2026-09-26。身份与事务接口见 [Foundation](FOUNDATION.md)。本文件不创建新的通话协议或统一对话状态机；说明已有机制能保证什么、世界与外部宿主仍需明确什么。

## 接入与提交

客户端持有用户授权的凭据，在请求鉴权层使用，不要求模型复制秘密。MCP 映射注册表工具与 schema；HTTP adapter 读取同一函数注册表，不复制业务规则。bootstrap / describe / discovery 与当前获准视图共同提供入口，不依赖旧模型上下文。

外部输入是指定函数的结构化调用。自然语言消息仅为 payload 文本；Runtime 不从文本推导“确认”“完成”或“仲裁结果”。确认必须通过世界声明的函数、对象引用和结构化参数，并通过身份、资格及状态检查。服务器能够接受并存储文本，不代表具有自然语言判断能力。

用户、Agent 和代码客户端走相同接口。世界作者的 entry_instructions 和 schema 是操作说明；其他角色提交的留言、证据和物品描述不是授权来源，不能变成控制指令。

## 接收、回应和业务结果

| 可记录的事实 | 不得由此推断 |
| --- | --- |
| 发件操作及消息已提交 | 接收方的 Agent 已启动或理解消息。 |
| 某客户端读到了事件页／游标 | 该主体已确认、已执行或完成请求。 |
| 接收方提交了关联回应 | 原事项必然成功，或回应中的自然语言声明已被验证。 |
| 世界函数接受结构化确认并改变状态 | 服务器自行理解了文本、替另一个主体表示意愿。 |

当前 recipient events / streams 提供投递记录及读取，不提供统一的业务 ACK、请求状态或对话终局协议。需要这些语义的世界必须声明对象 ID、回应关联、允许的提交者、前置状态、撤回／完成条件，并将仍需接续的事实持久化。具体通用字段与是否值得提取为辅助合同仍待设计，不能声称所有世界已经共享一套消息协议。

## 外部运行、轮次与等待

模型推理轮次由外部宿主管理；工具调用是一次 RPC；对话或任务的业务轮次由世界规则定义。三者不能混同。Runtime 不强制双方交替发言，不因 HTTP 成功就推进业务轮次，不替未回应主体作决定。

接收方宿主正在运行时，可读取事件或进行一次有界 wait。宿主不运行时，Runtime 只保留按合同需要的信息，不会创建接收方 Agent。外部宿主是否支持订阅、回调或调度由其能力和用户授权决定，不是当前 Runtime 已提供的唤醒保证。

wait timeout 只结束本次等待，不等于请求被拒绝、对话结束或业务截止时间到期。一次请求取消只停止本地等待；撤回已提交事项必须是单独的获准世界操作。原型默认不通过连续模型 turn 查询回复；合法的宿主长连接／重新订阅不能被误写成“一律禁止”。自动运行必须有外部授权、预算与停止条件，Runtime 不暗中发起无限等待循环。

消息对话无需普遍创建 Activity。仅有互斥控制要求的过程才使用租约与 fencing；共享资源冲突由世界事务检查。是否存在回复超时、晚到回复如何处理和何时允许重新发起，见 [OPEN_DESIGN](OPEN_DESIGN.md)。

## 断线、换客户端与缓存

客户端应保存未知结果操作的原 operation_id 和参数，恢复时先查回执，必要时仅重试原 ID。新 Agent 不必继承私人记忆，但应读取足以接续的当前获准状态。

事件读取不删除事件。读取游标是同步位置，不是业务完成标记；不同客户端不应靠一个共享读取位置隐式宣布对方已处理。需要独占处理时使用明确的世界状态／控制机制，具体通知消费合同不能靠猜测补上。

消息若只是临时交流，可按声明的保留期过期；若承载尚未结束的共同事项，仅把它放在短期事件／缓存里不足以支持恢复。世界必须另存必要状态，或明确将事项终止为过期状态。游标过期后重新加载快照，不伪造缺失历史，也不静默丢失仍有效的事项。

## Adapter 的最低责任

保持稳定工具映射与 schema，忠实返回业务错误；同逻辑重试复用 ID，新动作使用新 ID；区分 transport timeout、模型故障与世界拒绝；取消时停止本地等待；只对当前用户和视图应用响应，拒绝过期／乱序更新。客户端缓存、动画和模型总结不能写回为权威事实。

验收至少覆盖发现、连续结构化调用、同 ID 重放／冲突、等待有事件／超时、丢响应恢复、换会话；使用活动、共享流或保留功能时再加对应场景。不要求每种客户端支持 CLI、常驻连接或特定模型。历史 Pi / DeepSeek Harness 实验只证明当时组合，参见[验收范围](REFERENCE_GATE.md)。
