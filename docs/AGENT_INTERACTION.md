# L4：外部 Agent 接入与交互合同

复核：2026-10-04。本文说明外部 Agent／客户端与持久世界交互时，哪些事实可以成立、哪些不能靠推断补出来。它不创建统一聊天产品或强制所有世界使用同一会话状态机。

## 接入与提交

用户的密钥保管端完成进入证明并取得世界签发的本地调用凭据；外部 Agent／客户端可只持有用户交给它的有效凭据，不必再次进入或持有身份私钥。连接秘密由工具配置管理，不要求模型把秘密复制进自然语言上下文。

所有客户端最终都提交声明过的结构化 Query / Command。世界作者可以提供 schema、入口说明和可发现动作帮助客户端理解怎样行动；其他参与者发来的留言、证据和描述仍然只是世界数据，不会因为出现在模型上下文里就成为 Runtime 控制指令。

自然语言消息可以携带人的意图，但 Runtime 不读取句子含义后自行产生确认、完成或裁决。需要这些语义的世界必须定义相应 Domain Object、允许的提交者、结构化动作、前置状态和状态变化。

## 接收、回应与完成不是同一事实

| 已经知道的事实 | 不能自动推出 |
| --- | --- |
| 发送动作已经提交 | 接收方宿主在线、已读或理解。 |
| 某条通知已被读取 | 接收主体已确认、执行或完成事项。 |
| 接收方提交了关联回应 | 原请求已经被接受，或回应文本中的声明已经被验证。 |
| 世界规则接受了某个结构化确认动作 | Runtime 理解了自然语言并替参与者表达意愿。 |

Delivered、Read、Responded、Confirmed、Executed、Completed 是不同语义。具体世界可以有意省略某些阶段，但必须在自己的规则里明确合并，不能由客户端或 Runtime 猜测。

当前 Runtime 没有通用“会话已读／已确认／已完成”对象。Commons v2 已证明当前 Post / Reply / Conversation / Message 流程不需要这种 Runtime 原语；只有新的跨领域反例证明现有 State + Operation/Receipt + Event 无法可靠表达时，才重新评估 [OPEN_DESIGN](OPEN_DESIGN.md) 中的共同事项模型。

## 外部运行、离线与等待

模型推理轮次、一次 Runtime 调用、世界业务轮次是三种不同概念。Runtime 不强制双方轮流发言，也不因一次调用成功就自动推进业务轮次。

接收方宿主在线时，可以主动读取或进行一次有界等待；宿主停止时，Runtime 只保存合同要求的世界事实和通知，不会在后台创建该用户的 Agent、模型会话或新决定。

等待超时只结束这次等待，不等于世界请求被拒绝、对话结束或业务截止时间到期。取消本地等待也不会撤销已经提交的世界事实；撤回必须是另外一个获准的世界动作。

任何自动持续运行都由外部宿主基于用户授权、预算和停止条件决定。Runtime 不暗中启动无限模型轮询。

Shared Grove 的普通提问只获得读取工具，不能隐式产生移动、发表、创作实例、恢复目标或执行检查点。宿主在提交前固定请求用途；只有本人明确委托的执行请求关联当前任务与活动段并取得世界行动权。工具目录或物件动作菜单描述世界能力，不代表本次请求已有授权。模型不能通过重用旧目标、请求文字或历史段编号改变本次用途。

普通提问与目标执行沿用本人原主会话，但宿主请求的运行／空闲状态和原任务的结算状态分别保存。问答不修改原目标、已用请求、行动额度或接续资格；未确认停止的任何原生请求仍阻止新推理。明确接续保留同一任务、目标、原回执及累计用量；一次可追加至多八次模型请求，任务累计至多三十二次，不重置行动授权。世界控制授权具有稳定的非秘密标识；相同目标文字不能代替同一次授权。

## 断线、换客户端与恢复

客户端遇到未知写结果时，应保存原 Operation identity 和原意图，恢复时先读取持久 Receipt，必要时只重试原 Operation。使用新 Operation identity 重做未知动作可能造成真正的重复业务。

世界明确确认因临时结算而拒绝、原动作未提交时，外部宿主可以在原授权和请求预算内短暂有界等待，并重发原 Operation 及原参数。等待不改变观察、版本、数量或委托；取消、接管或原请求结束会关闭后续重发。当前状态不再符合前提时，必须重新读取并由参与者决定新动作，不能替换原意图。重发后失联仍是未知结果，不能沿用先前拒绝来断言未提交。暂忙、等待和最终恢复结果均须留有记录。

暂忙窗口限制等待和下一次发送，不截断已发出的原请求。收回控制后，只有确认原授权已经撤销、原模型会话空闲且已排空本机写入，才可核对原执行 journal：先查原 Receipt，缺失时核对永久原 grant、任务、段和旧令牌，再至多提交一次完全原封包。已有提交返回原 Receipt；未提交动作由撤销授权拒绝。不得重新授予控制、换观察或编号来完成原意图；不确定错误仍保留 unknown。缺少原授权关联的旧记录不能靠猜测恢复。

当前执行输入只重新呈现当前目标和偏好，历史创作请求继续保存在本人原会话与本机记忆中。按当前任务保留的原回执归组显示已确认行动，不因后来移动淹没先前投入；历史提交结果与新现场读数分开，归组不推算累计材料、不裁定自然语言目标，也不能把物件作者当作后来操作者。

原请求记录区分普通问答、明确委托与内容创作，历史读取返回原请求用途及可核对的任务关联；缺少可靠关联时明确为未知，不把所有用户文字都称作目标。旧用户指令只在推理副本呈现为没有当前授权的历史，原用户文字、工具输入输出及会话不改删。普通预检不重新下发旧目标或旧任务行动统计；需要历史时读取本人原来源。

执行请求达到上下文边界时，宿主只在当前请求身份可核验、至少已有一组完整终态工具反馈且没有未完成工具时记录可信让出。让出不是模型回答、完成声明或检查点；先封闭后续写入，确认原会话空闲、排空写入、核对原回执并读回，再在原任务与剩余额度内接续。首次输入自身过大、来源不匹配或未知写结果仍暂停。新准备读取可以作为防空转证据，但不增加行动数、不进入完成证据，也不授权普通模型错误自动重试。

本机请求、观察或行动审计保存失败会封闭后续模型推理和委托行动；模型收到的工具错误、预算让出或后来一次保存成功都不能自行恢复资格。恢复需确认原会话空闲、排空写入、核对原未知操作、撤销原行动权并取得新现场，再成功保存恢复事实。

本机执行的完整Provider请求保留128KiB硬上限，64KiB只是可展开旧历史池的最大额度。旧池必须先为完整当前用户／工具轮、正式SDK的系统与工具定义负载让出空间：有当前执行归属时按96KiB安全分段线收回旧工具对及索引，普通读取按128KiB硬线预算；首次SDK固定保留32KiB，其后只使用同provider／model／Native会话／agent正式body实测的固定负载及消息转换正向差额。原数据库与当前工具对不截断；旧历史可从正式来源入口有界查回，不增加当前观察或行动权。只有完整终态工具对、原请求归属及实际全包预算都核验后才可信让出，封段结算后继续同一有限任务；加载配置时读到旧让出状态只表示宿主已加载，新请求仍须自己的新证明。

执行载体可以替换。用户复制自己的本地记忆、上下文及有效世界连接配置到另一兼容 CLI 后，调用仍代表同一 Principal；世界不验证模型或工具是否为同一个 Agent。私人记忆的迁移由用户负责，Runtime 不保存或自动同步它。

世界事实的恢复以获准权威状态为准；用户迁移的私人记忆可以保留自己的目的、偏好和理解，但不能改变已提交事实。未决写入也须保留原 Operation identity 和原意图，避免新工具把未知结果当成从未执行。仍在进行的共同事项不能只存在于短期通知或客户端缓存中。

读取位置只代表同步进度。多客户端不能共享一个读取位置，然后把“有人读过”偷偷解释成“这个主体已经处理”。需要独占消费、ACK 或完成时，世界必须建立明确业务状态。

通知或历史过期后，客户端重新获取当前快照；不能伪造已经清理的历史，也不能因为历史丢失就静默把仍有效事项标记完成。

## Adapter / 客户端最低责任

- 同一业务意图重试时保留原 Operation identity，新动作使用新的 Operation identity；这不是更换 User Identity。
- 凭据轮换也保留稳定 operation_id；若响应丢失，先恢复 rotation receipt 或重放同一轮换操作，不能因为旧凭据已失效就另造一枚未知的新凭据。
- 区分传输失败、模型失败、世界拒绝和已提交业务结果。
- 忠实返回世界错误，不用“看起来成功”的 UI 掩盖拒绝。
- 对缓存和异步响应执行身份、版本与顺序校验，拒绝过期／乱序结果。
- 客户端总结、动画和本地状态不能写回成权威世界事实。

提交时的确认后果与随后读取的当前状态分别标明来源和读取时间；当前读取不能覆盖原回执。实际动作对象可以与用户最初选择不同，须分别记录，不能换掉原选择及其合同。对象已消耗、远离或不可见时，后续详情不可读不等于已确认动作被拒绝。

本机连接器的网页状态只提供明确形状的宿主信息、原发表物件引用和原回执显示事实，不透传现场、物件 `state/program`、完整过程或创作内容存储镜像。原提交的后果说明、位置、持有关系、材料消耗、转移和储能保留；提交时声明字段以历史事实行呈现，未知值仍是未知。当前对象详情通过 `client_read_request` 指向正式 `grove.client_inspect` 单独读取；它不能替代 `readback_actual` 或为原历史结果补造证明。内部记忆、Agent 事实接口、原会话和原回执不因网页投影而改写。

模型回复须能对应原任务、请求与会话，取消后保留为历史，不再作为当前结果展示。模型声明完成仍只是声明，程序确认的是实际提交与当前获准事实。整理旧机器现场可减少推理输入，但必须保留原文及可查来源，不删除人的聊天、发表定义、原回执和失败。

## EigenFlux 参考建议

参考其已经落地的分段接入与恢复方式，把“宿主适配可用、身份密钥可用、当前世界 Credential 可用、持续自动运行已获用户授权”分开表达。稳定本地连接配置可以缓存世界地址和本地 Credential，但 User Identity 本身由用户身份密钥决定，不随工作目录、新对话或某个世界的本地档案变化。

利用现有 bootstrap / describe / discover 先暴露当前获准入口，再按任务加载具体 schema。断线后从权威状态、Receipt 与同步位置恢复世界事实；私人上下文可由用户独立迁移。外部宿主负责有界等待、退避、取消和停止条件；Runtime 不因为参考项目有常驻 stream 就自动内置后台 Agent。

社交 Reference Application 可以借鉴“从来源内容发起、回复现有会话、对已有关系直接联系”等入口，但这些属于该应用的 L3/L4 规则。是否允许联系、是否形成关系、是否已读／接受必须由结构化状态与服务端规则决定，不能由一段聊天文字或通知读取代替。

### Shared Grove 本机委托与按需事实

新委托默认16次模型请求，显式最多32次；同一授权内自动接段，追加每批最多8次，旧任务不自动扩额。准备进展依据实际交付的新事实，输送元数据和全局时钟不算进展。纯观察目标可在真实本任务读取和最新读回后给出无写回执的完成声明；声明仍未被服务器认证为自然语言目标完成。

自动动作／检查点反馈给原回执与成本、当前相关物件及本人状态；`inventory_discovery` 和 `inventory_discovery_projection` 仅是最多8项的发现样本，没有版本、批次、状态或行动权限，也没有分页游标。完整背包从 `map_viewport` 读，再跟随正式 `inventory_next`；相关对象从 `grove.inspect` 读。明确不可读后的对象不能靠此前背包版本恢复授权。

不维护服务器私人草稿或AI对话记忆。原Native会话属于用户自己的宿主；本机只保留控制任务、精确回执恢复与用户明确设置的偏好，不自动重复积累或回放用户请求。旧本机请求字段原样保存但不再投影。公开改版以固定 `source_definition_ref` 另发新版本；来源不替代真实材料、权限或观察。
