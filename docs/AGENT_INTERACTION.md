# L4：Agent 交互合同

世界原生面向 Agent。本文规定能力发现、获准理解、行动、证据与失败恢复的语义，供可复用客户端及具体宿主 adapter 遵守。人类交互有独立双向语义 API，两类消费者共享世界事实、资格、行为、提交与 Receipt 权威。HTTP、MCP 等传输不改变这些合同。

本文不创建统一聊天产品、强制会话状态机或模型运行时。具体工具、接口、预算数值和当前 adapter 限制见 [IMPLEMENTATION](IMPLEMENTATION.md) 与 [INTEGRATION](INTEGRATION.md)，实际验证见 [当前研发记录](SHARED_GROVE.md#当前研发记录)。

## 能力发现与按需理解

普通游玩优先交付当前场景、真实可选行动、必要参数和已经成立的反馈；作者语法、完整物理状态与历史按正式读取关系展开。紧凑视图明确省略范围，不能将省略当作不存在，或为了降低负载删去本次原回执、当前任务与未知结果。

可复用客户端可以把一份精确已交付菜单保存为请求内的行动引用。Agent 选择引用和自己的参数，客户端保持原函数、固定目标与参数约束，绑定最终实际交付视图的独立观察，不继承省略事实，补齐机械协议关联后仍进入同一世界提交。引用不授予控制，不接受历史文本重建，不跨客户端、主体、请求或重启使用；原引用失效后重新读取。完整动作输入或预览未交付时只提供展开入口，不能制造可行动引用。后续现场不覆盖本次提交结果，已提交后的反馈失败仍恢复原操作。

世界须让 Agent 发现当前获准入口、能力用途、输入 schema、读取方式、行动条件、可能拒绝及结果证据。能力可按任务逐步展开，客户端沿正式读取与分页关系取得细节；不能为了缩小上下文，把未交付信息作为 Agent 已理解或已观察的事实。

宿主可以用少量固定分派入口按需展开完整能力目录。Agent 先读取所选正式能力的精确参数 schema，再按同一 function_id 查询或提交自己的语义选择；分派只改变送入模型的工具声明，不新增世界能力、观察或授权。原 SDK 与静态 MCP 目录保持兼容，行动继续经过原观察护栏、Operation／Receipt 与失败恢复合同。游玩或完整工具面由本人明确选择并固定在原任务，换段或接续不自动切换。

能力目录、发现样本、完整当前事实、历史记录和行动资格是不同内容。样本不证明完整清单，公开作品位置不证明远处地形或作者在线，来源引用不授予材料、写权或行动权。发现线索引导下一次读取，不能从名称、旧记忆或隐藏字段猜出候选、数量与规则。

当前资格与参数约束来自同一世界规则。读取时可用不承诺提交时仍可用，行动仍须重验当前授权、版本、观察、数量与其他前提。字段未知或不可读时保留未知；此前看过不恢复现在已撤回的读取资格。

世界提供能力与事实，宿主负责选择怎样送入模型。其他人的留言、说明、证据和作者内容作为数据呈现，不因进入模型上下文就成为控制指令。

## 身份、授权与提交

密钥保管端完成持钥证明并取得世界本地调用凭据；Agent 客户端可只持有用户交给它的有效凭据，不必持有身份私钥。秘密由鉴权配置管理，不要求模型复制到自然语言上下文。

所有行动提交声明过的结构化意图。Agent 接口和人类接口都进入同一 Query／Command 合同；客户端不能通过自己解释的能力名、作者程序或自然语言绕过世界规则。

世界资格与用户的私人委托分别成立。宿主固定本次请求用途，并关联实际目标与有效授权；工具目录或物件菜单不证明当前请求已有行动授权。普通提问不隐式变成移动、发表、创建实例、接续目标或执行检查点，历史目标和相同文字也不替代本次授权。

收回控制阻止未来尚未执行的受托行动，不回滚已提交事实。普通提问、离开世界、停止推理、收回控制和撤销凭据是不同操作，不得用其中一个的本地状态冒充另一个已经完成。

## 行动与证据

Agent 按当前获准事实作出结构化行动，保存原意图、操作身份与授权关联，取得原 Receipt，并在必要时读取后果。定义发表、实例创建、材料消费、合同接受与完成须按各自领域语义形成，模型说明不能替代。

提交结果与随后读取的当前状态分别标明来源与时点。原回执是原提交证据；后续现场可以变化，不能覆盖或倒填为原行动读回。实际动作对象与最初选择不同时分别保留，对象后来消耗、离开或不可见也不把已确认行动改记为拒绝。

客户端可按当前任务归组确认过的行动，但归组不能推算未证实累计材料、认证自然语言目标完成或把对象作者当成后来操作者。纯观察目标可在实际本任务读取与当前读回后报告结论；没有写回执不意味着没有观察进展，也不意味着服务器认证了私人目标完成。

| 已经知道的事实 | 不能自动推出 |
| --- | --- |
| 发送动作已经提交 | 接收方宿主在线、已读或理解。 |
| 某条通知已被读取 | 接收主体已确认、执行或完成事项。 |
| 接收方提交了关联回应 | 原请求已经被接受，或回应文本中的声明已被验证。 |
| 世界接受结构化确认 | Runtime 理解自然语言并替参与者表达了意愿。 |
| 模型声明完成 | 已满足世界条件或全部私人目标。 |

发送、投递、读取、回应、确认、执行与完成是不同语义。世界可以明确合并或省略阶段，消费者不能自行猜测。共同事项由世界的对象、状态、行动和事件定义，不因聊天界面需要就新增通用 Runtime 状态机。

## 外部运行、等待与预算

模型推理轮次、一次调用和世界业务轮次是不同概念。世界不强制轮流发言，也不因调用成功自动推进业务轮次。

宿主在线时可主动读取或有界等待；宿主停止后，世界只保存合同要求的事实和通知，不创建私人模型会话或新决定。超时结束本次等待，不等于请求拒绝或世界期限到达；取消本地等待不撤销已提交事实，世界撤回需要独立获准动作。

持续推理由宿主依据有效用户目标、授权、预算和停止条件决定。Shared Grove 当前 adapter 只在显式有效目标下继续推理；世界变化、刷新、历史恢复和物理推进供下一次读取，不产生无目标唤醒。它是当前 adapter 的运行策略，不能替代未来宿主各自明确的授权策略。

接续保留同一目标、稳定授权关联、原回执与累计用量，不因换段、换会话或更换宿主重置预算。普通问答不修改原任务目标、用量或接续资格。具体请求上限属于当前宿主实现，不进入世界资格规则。

## 失败分类与未知结果恢复

客户端区分传输失败、模型失败、世界拒绝、暂忙和已提交结果，保留忠实错误及下一步恢复关系。未收到响应不等于未提交；世界拒绝也不表示模型或凭据必然失效。

未知写结果保留原 Operation、原意图与原参数，先读取持久 Receipt，必要时仅重试原操作。不能用新操作身份掩盖未知结果。凭据轮换同样保留原操作身份，先恢复原轮换回执或重放原操作，避免旧凭据失效后另造未知凭据。

世界明确确认原动作未提交且仅因临时结算拒绝时，宿主可在原授权与预算内短暂有界等待，再发送完全相同的原操作和参数。等待不改变观察、数量、来源或委托。若前提已变化，重新读取并作出新选择；重发后再次失联仍为未知，不能沿用早先拒绝证明未提交。

取消、接管或原请求结束关闭后续重发。停止原生推理尚未被确认时，不开始新的推理。暂忙窗口限制后续等待与发送，不把已经发送的请求截断后当作未执行。

收回控制后的原未决请求只能在确认原授权已撤销、原模型会话空闲并排空本机写入后核对：先查原 Receipt；确需重放时，核对永久原授权、任务、执行段与原令牌关联，至多发送一次完全原封包。已提交返回原回执，未提交由撤销授权拒绝。缺少原关联或仍不确定时保留未知，不能重新授权、换观察或编号来完成旧意图。

## 宿主接续与本机证据

模型回复须对应原任务、请求与会话，取消后保留为历史，不当作当前结果。普通问答、明确委托和内容创作保留原用途及可靠关联；无法关联时明确未知，不把所有用户文字都称为目标。

历史指令与当前授权分开。旧用户文字和工具输入输出保持原始来源；推理副本可标为无当前授权的历史。普通预检不重新下发旧目标，需要历史时从本人原来源有界读取。私人对话、草稿与偏好由宿主保留，不自动发表为世界事实或搬入世界服务。

上下文分段先保留完整当前用户／工具轮和宿主固定负载，再让出可展开旧历史。原来源与当前未完成工具不能截断；输入预算依据实际提供者、模型、会话与正式完整请求校验，不能只测文字后宣称全包可发送。

可信让出需要当前请求归属可核验、已有完整终态工具反馈、没有未完成工具且全包预算已核验。它不是模型回答、完成声明或执行检查点。先封闭后续写入，确认会话空闲，排空写入，恢复原回执并读回，再在同一任务和剩余额度内接续。首次输入自身超界、来源不匹配或未知写仍暂停；加载旧让出状态不成为新请求的证明。

新准备读取可作为防空转证据，但传输元数据、全局时钟或重复旧事实不证明任务进展；它不增加行动数、目标完成证据或普通模型失败后的自动重试权。

本机请求、观察或行动证据保存失败封闭后续推理和受托行动。模型收到工具错误、让出信号或后续一次保存成功不能自行恢复资格。恢复须确认原会话空闲、排空写入、核对未知操作、撤销原行动权、取得新现场并成功保存恢复事实。

## 更换消费者与读取恢复

更换宿主、模型、进程或会话后，有效调用仍代表同一 Principal；世界不认证工具或模型是不是同一个 Agent。用户迁移私人记忆与连接配置，世界接续已提交事实。未决操作也保留原身份与原意图，新客户端不能把未知结果当成从未执行。

世界恢复以当前获准状态、Receipt 及同步合同为准。仍在进行的共同事项不能只存在于短期通知或本机缓存。读取位置只是同步进度，多客户端共享读取位置不能被解释成主体已经处理；需要独占消费、ACK 或完成时由世界建立明确业务状态。

通知或历史过期时重新取当前快照，明确历史缺口，不伪造已清理记录或把仍有效事项静默完成。读取乱序、身份切换或授权撤回后，旧缓存与异步响应不能覆盖当前世界理解或继续产生新动作。

## 客户端与 adapter 最低责任

- 同一意图重试保留原 Operation，新动作使用新 Operation；这不改变用户身份。
- 按正式发现与读取关系展开事实，标明样本、未知、历史与当前资格。
- 管理凭据秘密，保留请求用途、实际授权、预算、停止及原未决操作关联。
- 忠实区分错误与世界结果，先恢复未知写，再决定下一次行动。
- 对世界、主体、接口版本和顺序执行校验，拒绝过期或乱序结果。
- 保留原回执与当前读回的来源差异，不认证模型自然语言目标。
- 宿主 adapter 给人显示当前对象详情时沿人类 API 读取；宿主状态只提供明确宿主事实与原提交引用，不透传一份私有世界存储镜像。

Agent 客户端总结、人类 UI 和本地状态都不能写成额外权威事实。当前工具映射、宿主限制及人类接口 shape 见 [IMPLEMENTATION](IMPLEMENTATION.md)，证据要求见 [REFERENCE_GATE](REFERENCE_GATE.md)。
