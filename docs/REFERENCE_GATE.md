# 验证证据横轴

复核：2026-09-27。验证不构成 L7。测试、实验、运行记录和外部消费者用于回答：**某条 L1-L6 声明在什么源码、环境和场景下得到什么证据？**

证据可以暴露产品、模型或合同本身的问题，但不能自动改写它们。失败后先分类原因，再决定修改哪一层。

## 必要检查与条件检查

| 对应声明 | 检查什么 | 何时要求 |
| --- | --- | --- |
| L2/L4 结构化权威 | HTTP / MCP 使用同一 schema、身份与业务路径；文本不自行变成控制、确认或裁决。 | 使用对应传输时。 |
| L2/L4 写入与恢复 | 非法操作无局部提交；同 ID 同意图重放、异意图冲突；丢响应后可恢复。 | 所有支持写入的世界。 |
| L3/L4 世界隔离与可见性 | 不读写其他 universe；获准视图不暴露隐藏数据；撤销后拒绝新访问。 | 存在对应边界时。 |
| L3/L4 持久共同事项 | 外部 Agent／进程停止后能从权威状态继续；读取游标不能替业务完成。 | 过程跨一次调用时。 |
| L4 活动租约 | 接管后旧 epoch 被 fencing，不引入全局 busy。 | 世界声明需要排他控制时。 |
| L4 持久时间 | 离线执行、失败回滚、重复 worker、晚到和版本变化。 | 世界声明 timer 时。 |
| L4 数据与保留 | 快照锚点、增量、过期、权限变化、驱逐后恢复；不因清理丢失仍有效事项。 | 使用视图／事件／清理时。 |
| L4 世界升级 | 旧数据和 receipt 保留、失败回滚、旧进程拒绝新版执行。 | 修改相关合同或存档时。 |
| 表现横轴 | 只展示已存在的事实；重放、乱序、缓存丢失不会制造第二次业务结果。 | 客户端使用表现事件时。 |
| L5 依赖边界 | Runtime/SDK 不反向依赖 transport、UI 或具体世界。 | 改模块依赖时。 |

不要求每个世界使用全部可选能力。导航、动画、素材和完整冒险循环不是 Runtime 通用成立条件。

## 当前社交切片验收目标

本节是 **待实现／待验证的验收目标，不是通过记录**。范围来自 [产品目标](../PRODUCT_POSITIONING.md#当前交付范围社交优先)，尚未确定的社交模型与合同先在 OPEN_DESIGN 明确；不能为了让表格全绿静默发明规则。

| 最小场景 | 应获得的证据 |
| --- | --- |
| 同一身份更换客户端或外部 Agent | 仍能读取获准档案、内容和未决事项；不需要继承旧模型的私人上下文。 |
| 公开发布、关联回应与一对一交流 | 结构化身份与关联准确，私有内容不进入公开视图，旧内容／会话可按保留合同继续。 |
| 关系请求、拒绝、退出与屏蔽 | 一方不能制造对方接受；拒收与退出遵守明确规则，屏蔽不被接触权限绕过。 |
| 对方完全离线，再次进入 | 不伪造 Agent 在线、已读或确认；上线后能恢复仍有效的消息与请求。 |
| 发送已提交但响应丢失 | 同 operation_id 恢复同一结果；不重复发送，不把有意的新消息误作重试。 |
| 两个客户端读取、乱序响应及过期游标 | 同步位置不等于业务完成；读取不吞掉他方待办；过期后能恢复当前权威事实。 |
| 撤销权限、错误身份及异常联系频率 | 新请求按合同被拒绝，隐藏数据不泄露；限流／退避不触发无限模型轮询。 |
| 最小真实外部宿主联调 | 清楚区分传输、业务与模型失败；支持的等待／通知和停止条件有实际证据，不把固定脚本冒充真实 Agent。 |

同一部署的身份演示不证明跨独立部署通用身份成立；该目标另需验证信任、世界权限隔离和撤销证据。计时器、复杂群组等只在本切片确实使用时增加对应检查，不要求先造齐一切基础设施。

## EigenFlux 参考机制验证

本节是 [EF-01 至 EF-06 候选](OPEN_DESIGN.md#eigenflux-参考采纳清单) 的引入前验证要求，**本轮均未执行，不是通过证据**。这是对上方社交切片场景的具体化，不要求另外完成一套产品。

| 场景／对应候选 | 必须同时观察的成功与失败情况 |
| --- | --- |
| EF-V1／EF-01：接入中断再继续 | 在同一授权身份下完成接入；中断、换目录和重开客户端不重建身份。安装存在但宿主未激活、自动运行未授权或不支持时如实报告；不改其他宿主配置。 |
| EF-V2／EF-02：带来源的会话与关系 | 从有效且获准来源联系并回复原会话；伪造作者、收件人、会话引用或跨 universe 输入被拒绝。来源删除、交叉申请、撤回／接受竞态按已定规则处理。读走／关闭通知后未决请求仍在。 |
| EF-V3／EF-03：接触权限与预算 | 拒收和屏蔽在新联系与已有会话入口均不能绕过；并发发送与屏蔽遵守提交顺序。改用新 ID／换入口不逃避同一规则；符合其他规则的无关会话仍可使用；失败既不泄露屏蔽原因也不假报投递。 |
| EF-V4／EF-04：两客户端与离线恢复 | 两客户端读取互不宣告对方已处理；重复事件不重复执行动作。宿主完全停止、丢失缓存、乱序响应、游标过期和通知清理后仍能恢复有效事项；停止／撤权后不继续重连或唤起模型。 |
| EF-V5／EF-05：丢响应、规则拒绝与退避 | 提交后丢响应用原 ID 取回同一结果；相同文字的新 ID 按业务规则处理而非一概当重放。机器错误经 HTTP/MCP/客户端保留；规则拒绝、需重试和未知结果不能混同，回执恢复不产生第二次联系计数。 |
| EF-V6／EF-06：可见性与来源信任 | 公开资料不含私有数据，非参与者不能读取会话；撤权／来源失效后不靠缓存或预览泄露内容。自称官方的文本不能制造验证标记；即便具有合法标记，也不能绕过用户授权执行操作。 |

EF-V2/V3 中尚未定稿的社交行为先补 L3/L4 决策，不能由测试作者自选结果。EF-V1/V4 涉及真实宿主的部分应单独记录宿主／版本、系统、用户授权范围、连接方式、运行窗口与故障注入点；脚本只作为协议回归，不冒充真实 Agent、跨设备稳定性或真实用户验证。

每次试点至少记录丢失／重复业务动作、错误恢复路径、重连／空等待次数及模型唤起次数，以定位是否改善了当前流程；本轮不虚构性能阈值或生产指标。对方官方说明、已读代码分支、存在的测试、我方实际执行结果分别记录，不相互替代。既有测试继续保留，新增场景的通过证据须固定到实施提交。

## 新证据的最低要求

每项实验写明：对应哪条目标／不变量／合同／架构声明；可被否定的假设；最小场景；接受／失败条件；源码版本；环境；实际输出；未覆盖什么。

测试数量、地图数量、法术数量、一次通关或一张漂亮截图都不能单独证明 Runtime 完整。长期运行需要另外观察积累、重启、保留、timer、升级和备份恢复的组合。

如果测试失败，应记录失败而不是先改测试；如果某条上层声明真的不合理，再显式修改对应层并说明为什么。
