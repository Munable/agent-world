# Runtime 验收范围

复核：2026-09-26。验收对象是世界 Runtime 的具体合同，不是完整游戏、完整社交产品或所有场景的通用性。产品范围以[产品定义](../PRODUCT_POSITIONING.md)为准。

## 必要检查与条件检查

| 能力 | 检查什么 | 何时要求 |
| --- | --- | --- |
| 结构化接入 | HTTP / MCP 使用同一 schema、身份与业务路径；文本不成为控制指令。 | 使用对应传输时。 |
| 写入与恢复 | 非法操作无局部提交；同 ID 同意图重放、异意图冲突；丢响应后恢复。 | 所有支持写入的世界。 |
| 世界隔离与可见性 | 不读写其他实例；获准视图不暴露隐藏数据；撤销后拒绝新访问。 | 存在对应身份／可见性边界时。 |
| 持久进行中事项 | 外部 Agent／进程停止后，从持久状态继续；旧继续请求被正确拒绝。 | 过程跨越一次调用时。 |
| 活动租约 | 接管后旧 epoch 被 fencing，不引入全局 busy。 | 世界声明需要排他控制时。 |
| 定时事项 | 离线执行、失败回滚、重复 worker、晚到与版本变化。 | 世界声明 timer 时。 |
| 事件、缓存与保留 | 快照锚点、增量、过期、权限变化、驱逐后恢复；不丢未决业务。 | 使用视图／事件／清理时。 |
| 世界升级 | 旧数据和回执保留、失败回滚、旧进程拒绝新版执行。 | 改变相关合同或存档时。 |
| 表现辅助 | 仅展示服务器已提交事实，去重与因果顺序正确。 | 客户端选用表现事件时。 |

不要求每个世界先使用全部可选能力。导航、朝向、行走动画、素材、完整冒险循环不是 Runtime 的通用门槛。发现具体通用缺陷即可修复，不必先开发完整游戏或固定数量的新世界。

## 已有证据入口

`tests/test_reference_boundary.py`、`tests/test_reference_transport.py`、`tests/view_client.test.mjs` 和 `tools/check_package.py` 保留原 RF1 有界测试。独立目录加载与 wheel 测试证明模块／包边界，不证明开发者体验或任意世界都成立。

[Foundation audit](FOUNDATION_AUDIT.md) 是 2026-09-22 的历史执行记录。早期 Pi / DeepSeek Harness / OpenCode 的版本、观察结果及限制保留在 [2026-09-21 原始接入记录](https://github.com/Munable/agent-world/blob/3fbb6378d9edcfa8b58a5d1d09c610037bf4c2f6/docs/AGENT_ADAPTER_CONTRACT_V01.md)。它们不是当前全部宿主的兼容性承诺，也不代表本轮重新运行过测试。

## 新实验的最小要求

每项实验写明一个可被否定的假设、最小场景、接受与失败条件、源码版本及实际输出。优先复用现有示例；没有覆盖的新交互才加最小夹具。测试数、地图数、法术数都不直接证明 Runtime 完整。

长期运行需要单独观察积累、重启、保留、定时器和升级的组合，不能把多次短链通关称为长期运行证明。未决逻辑及验证清单集中在 [OPEN_DESIGN](OPEN_DESIGN.md)。
