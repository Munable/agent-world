# 验证证据横轴

复核：2026-09-27。验证不构成 L7。测试、实验、运行记录和外部消费者用于回答：**某条 L1-L6 声明在什么源码、环境和场景下得到什么证据？**

证据可以暴露产品、模型或合同本身的问题，但不能自动改写它们。失败后先分类原因，再决定修改哪一层。

## 必要检查与条件检查

| 对应声明 | 检查什么 | 何时要求 |
| --- | --- | --- |
| L2/L4 结构化权威 | HTTP / MCP 使用同一 schema、身份与业务路径；文本不自行变成控制、确认或裁决。 | 使用对应传输时。 |
| L2/L4 写入与恢复 | 非法操作无局部提交；同 ID 同意图重放、异意图冲突；丢响应后可恢复。 | 所有支持写入的世界。 |
| L3/L4 世界隔离与可见性 | 不读写其他 universe；获准视图不暴露隐藏数据；撤销后拒绝新访问。 | 存在对应边界时。 |
| L3/L4 持久共同事项 | 外部 Agent／进程停止后能从权威状态继续；读取游标不能替业务完成。 | 过程跨一次调用时。 |
| L4 活动租约 | 接管后旧 epoch 被 fencing，不引入全局 busy。 | 世界声明需要排他控制时。 |
| L4 持久时间 | 离线执行、失败回滚、重复 worker、晚到和版本变化。 | 世界声明 timer 时。 |
| L4 数据与保留 | 快照锚点、增量、过期、权限变化、驱逐后恢复；不因清理丢失仍有效事项。 | 使用视图／事件／清理时。 |
| L4 世界升级 | 旧数据和 receipt 保留、失败回滚、旧进程拒绝新版执行。 | 修改相关合同或存档时。 |
| 表现横轴 | 只展示已存在的事实；重放、乱序、缓存丢失不会制造第二次业务结果。 | 客户端使用表现事件时。 |
| L5 依赖边界 | Runtime/SDK 不反向依赖 transport、UI 或具体世界。 | 改模块依赖时。 |

不要求每个世界使用全部可选能力。导航、动画、素材和完整冒险循环不是 Runtime 通用成立条件。

## 新证据的最低要求

每项实验写明：对应哪条目标／不变量／合同／架构声明；可被否定的假设；最小场景；接受／失败条件；源码版本；环境；实际输出；未覆盖什么。

测试数量、地图数量、法术数量、一次通关或一张漂亮截图都不能单独证明 Runtime 完整。长期运行需要另外观察积累、重启、保留、timer、升级和备份恢复的组合。

如果测试失败，应记录失败而不是先改测试；如果某条上层声明真的不合理，再显式修改对应层并说明为什么。
