# L4：世界数据、授权投影与缓存合同

复核：2026-09-27。本文定义世界事实、历史、通知、授权投影和缓存之间的语义关系。具体表名、端点、大小上限和客户端文件见 [IMPLEMENTATION](IMPLEMENTATION.md)。

## 数据职责

| 数据类别 | 语义责任 |
| --- | --- |
| 用户身份／参与资料 | 用于识别参与者；跨独立部署统一身份仍未完整实现。 |
| 当前世界状态 | 世界当前权威事实，是恢复进行中业务的主要来源。 |
| Operation / Receipt | 防止未知结果和重试造成重复提交，并提供已提交结果证据。 |
| 未决 Domain Object | 保存跨调用仍需继续的请求、交易、案件、任务等业务事实。 |
| 状态历史 | 用于受控审计／恢复场景，不等于当前状态，也不保证永久保留。 |
| 通知／共享观察 | 告知已经发生的事实；不自动成为接收者 ACK。 |
| 授权 View | 根据当前事实和当前权限计算的派生投影。 |
| Sync Position / Cache | 可重建的同步辅助数据，不是业务事实来源。 |
| 私人推理／未提交计划 | 属于用户／外部 Agent 宿主，不要求上传 Runtime。 |

被明确提交并经世界规则接受的公开计划、消息或第三方意见可以成为世界数据；这与 Agent 私人思考是两回事。

## 当前状态、历史和通知

当前状态、历史和通知承担不同职责，不能互相替代：没有通知的状态变化仍然可以成立；清理通知不能删除当前世界事实；历史存在也不意味着普通 Agent 自动拥有读取全库审计记录的权限。

仍未结束的业务事项必须在当前权威状态或等价持久 Domain Object 中保留足够信息。不能因为短期通知、View cache 或历史被清理，就让事项凭空消失或完成。

## 授权 View

View 是对当前世界事实的授权投影。每次创建或同步投影时都必须按当前主体和当前权限重新判断可见性；隐藏数据不能先完整发送给客户端，再依赖 CSS 或前端逻辑“藏起来”。

View 中的实体结构、资源引用和 renderer hint 都由世界声明，但它们只是派生表示，不为 Runtime 引入固定 HP、坐标、任务、好友等领域对象。

资源引用和表现提示应当作为数据处理，而不是可执行代码或凭据载体。已经看过的信息无法通过后续撤权从人的记忆里收回，但撤权后不得继续提供新的受保护内容。

## Snapshot、增量与 Sync Position

Snapshot 应代表某个一致读取边界下的授权投影。增量同步必须明确基于哪个 Snapshot／Sync Position；只有基线匹配的更新才能应用。

增量是“从旧投影到新投影的差异”，不是世界动作时间线，也不保证保留所有中间状态。可见性撤回导致的实体删除也必须作为投影变化表达。

Sync Position 必须绑定足够的身份、World Instance、View 和版本上下文，避免把一个主体／视图的缓存位置拿给另一个主体／视图继续使用。

Sync Position 过期、驱逐、版本不兼容或校验失败时，应明确要求重新 Snapshot；不能静默继续一个已经失去基线的数据流。

## 缓存

服务端 View cache 和客户端副本都属于可重建派生数据。缓存命中不能跳过权限复核；缓存丢失不能改变世界业务结果。

cursor 相同不证明请求没有执行，cursor 变化也不证明业务事实一定发生变化。业务判断必须读取世界语义本身，而不是从缓存 token 猜测。

数据清理与长期恢复边界见 [RETENTION](RETENTION.md)；交互接续见 [AGENT_INTERACTION](AGENT_INTERACTION.md)。
