# Shared Grove（溪源）：当前官方世界

复核：2026-10-07。本文是官方 World Package 的当前合同与入口，不改变 Runtime 的领域中立、密钥身份或提交语义。**已授权本地切片验收通过；真人趣味性、跨机器和负载未验证。** 本轮是两个独立本地模拟玩家、真实 OpenCode 与实际浏览器验证，不是两名真人或完整 MMO。旧 Frontier 的实测结果不计入本世界。

## 玩家的体验与职责

第一切片面向 2–4 人。每人连接自己的 OpenCode 后进入同一个二维世界，用键盘移动、鼠标查看并选择真实行动。个人目的由自己决定；Agent 解释现场、回应用户、贡献内容，玩家亲自行动。没有固定章节、统一任务、自动玩家或逐项审批队列。

程序生成提供可探索的起点和空间；探索后出现的有界公开机会允许 Agent 贡献新物件、布局与短描述。别人的取放、容器内容和材料变化会改变自己能看到、拿到和继续做的事。进展沿实际沟通与交互轮次记录：发现 → 玩家选择 → 真实行动 → 共享后果 → 下一轮选择，并判断功能发现、探索路径与体验深度；运行天数、日活或每日任务不衡量产品完成。

## 共同事实与材料规则

| 领域事实 | 共同规则 |
| --- | --- |
| 空间与位置 | 四向单格移动；阻挡、距离和版本由服务器检查。地图按 16×16 chunk 保存，视口与查询范围有界。 |
| 实体与材料 | 木、石、布及其能力、位置、状态、版本是结构化事实。行动根据能力开放，不能凭名称或描述制造效果。 |
| 归属与容器 | 物件只能有一个实际所在位置／持有者／容器。取放、开关、存取须满足距离、容量和当前版本，整个变化原子提交。 |
| 水与湿／干 | 水量、容器容量、内容和湿度使用同一模型；装水、倒水和降雨真正改变状态。文案中的水不等于可用水量。 |
| 火与燃烧 | 点燃、燃料和湿度影响声明过的燃烧过程；效果由代码结算，Agent 不自行宣布烧毁或免疫。 |
| 来源与恢复 | 用户内容保留来源；系统过程标记系统来源。同钥重新进入接续原身份与已提交事实，未知写结果按原 Operation 恢复。 |

当前行动目录按实体能力返回：取／放、开／关、存入／取出、装水／倒水、点燃。客户端只呈现服务器返回的可用行动。完整战斗、死亡、经济模拟、自由流体、第三方插件和多 CLI 不属于第一切片。

服务器是普通中心权威服务器，统一保存位置、归属、容量、材料和过程；不运行每用户模型、GM 或后台替玩家作决定。正常过程按天气 → 湿度 → 燃烧 → 漂流的声明顺序推进，物理计时采用一秒逻辑步。批量扫描只是有界调度方式，不能因实体密度或扫描间隔拉长降雨、干燥或燃烧的规则时长。服务停机时暂停过程，恢复后不根据离线时长补结算。雨、湿度与燃烧保留必要的真实计时，时间也用于资源与来源记录；这些过程时钟不能折算成沟通轮次或体验深度。

固定秒步实现已完成：准入上限为合计 128 件受湿或已预留降雨／漂流的实体、16 件燃烧实体、合计 16 件燃烧容器后代，以及 4 个降雨／漂流事件。超限请求原子拒绝，合法容量内继续推进时钟，保持每次提交 512 次 state write 的边界。本轮 9 项规则回归通过；低／高密度的 12 ticks 逐 tick 对照在雨湿、自然干燥、燃料与毁坏上相同。该定向结果不等于完整产品验收。

## 生成与事件

程序生成和 Agent 贡献使用同一个有限材料、实体与能力目录。生成上下文提供有界公开现场与一个可领取机会；领取会改变机会归属，因此是写入。提交必须通过机会归属、到期、版本、区域冲突、数量和预算检查，不能提交任意状态补丁、改规则或覆盖已有内容。

生成是显式的游戏内操作，由生成按钮／接口发起；普通提问只回应，不被当作发布授权。完整蓝图路线为：连接器以玩家同一身份调用实际 `grove.generation_context`，取得原机会 ID／版本、有界公开事实、真实坐标、目录和当前 schema，再交给用户自己的 OpenCode。每个真实机会使用一个独立、禁止所有工具的蓝图会话，避免主聊天历史混入；主身份与私人记忆仍保留。模型一次返回结构化 blueprint，连接器依原机会和版本自动调用 `grove.content_submit`，读回回执与现场。玩家无需审提案，服务器不运行模型，也不要求模型每次自主遍历 MCP 并拼接整串调用。

可纠正的蓝图校验失败至多触发一次纠正，复用本机会的蓝图会话、原事实与待纠正蓝图，最多增加一个 OpenCode message 请求，并计入原预算；机会到期、归属或版本冲突须按真实拒绝停止，不重置额度无限重试。未知写结果先用原 Operation 查 Receipt 或原请求重放，不生成新操作或新机会掩盖未知结果。只有接受后的结构化结果才能显示发布成功。

已探索区域可以出现短时降雨和水上漂来的容器。雨作用于真实湿度与燃烧，漂来容器的容量、内容、位置与取放使用同一物件模型。事件提供新处境，不强制玩家接受任务；预算耗尽、机会过期或冲突时明确停止或拒绝，无人工批准环节。

## OpenCode 与入场

网页连接本机 OpenCode 的专用会话。首次连接保留专用会话的实际 MCP 世界读取与完成回应门槛；安装、配置、健康检查或下载凭据不等于 Agent 已接上。服务器的 `grove.join` 仍是普通持钥动作，不认证外部工具或模型本体。专用会话向 Agent 提供获准现场、手册和内容能力，不提供移动或替玩家操作的工具；后续显式生成可以使用上述连接器准备现场与自动提交路线。

用户宿主控制模型、私人上下文与调用成本。会话的调用量、超时、并发和输出必须有界，取消或额度耗尽后停止；客户端不能靠无限轮询假装陪伴。身份仍只认用户密钥，不建立 AgentIdentity；连接断开、离开网页、停止推理和撤销 Credential 是不同操作。

当前每次宿主请求上限为输出 4096 tokens、8 steps、16 次工具调用、150 秒；蓝图会话另禁止所有工具。本轮来源明确将总上限扩至 **18 个 OpenCode message 请求，含纠正**，实际使用 14 个；provider 内部 assistant steps 为 18，另记且不冒充请求次数。provider 返回的 cost metadata 为 0，账单成本未核实。两次真实入场、双向布局生成、降雨和漂流发布均通过本地切片门槛；主会话随后实际读取现场并给出两种选择，没有移动或发布。
