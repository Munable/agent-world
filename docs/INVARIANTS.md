# L2：系统不变量

这里记录的是 **即使数据库、协议、模块和界面全部更换，仍然必须成立的系统性质**。实现做不到时，应记录缺口，而不是把缺口改写成原则。

## 权威与主体

### I1 权威事实只能来自声明过的机制

世界事实的成立必须来自经过身份、授权和世界规则检查的结构化行动，或来自预先声明的系统机制。自然语言可以作为消息、说明或证据，但文本本身不能自动变成确认、授权、完成或裁决。

Agent 接口、人类交互接口及不同传输共用同一个事实、资格、行为、提交和 Receipt 权威。发现结果、接口投影、可复用客户端、宿主 adapter 与 renderer 不能各自裁决另一套资格或形成另一套世界结果。MCP 同样是 API，传输名称不改变这条边界。

### I2 一个主体不能单方面制造另一个主体的意愿

某主体的确认、回应、决定或授权必须可归因于该主体自己的获准行动，或可归因于事先明确的委托／第三方规则。任何参与者都不能只写一句“对方同意了”就替另一个主体创造事实。

### I3 用户身份只认密钥，身份与领域授权必须分离

用户身份的根事实只有一个：**当前调用者是否能证明自己持有某个身份公钥对应的私钥。** 同一个公钥在任何世界都表示同一个底层用户身份；不同公钥必须视为不同身份。Runtime／世界不得根据姓名、头像、设备、档案内容、自然语言声明、人工判断或“看起来像同一个人”把两个密钥合并。

世界第一次见到某个公钥时，可以为它创建本世界自己的参与档案；以后该公钥再次完成持钥证明时，只能回到这个公钥在本世界已有的档案。档案不是跨世界身份本身，也不要求跨世界同步。

**密钥丢失就是身份丢失。** 旧公钥对应的世界档案可以继续作为历史事实存在，但没有原私钥就不能再证明对它的控制权。系统不提供身份密钥找回、换钥继承、身份合并、恢复机构或“认人不认钥”的后门；新密钥就是新身份。

证明调用者是谁，也不等于证明调用者可以执行任意世界动作。身份密钥、世界本地调用凭据、世界资格、对象状态和具体行动授权是不同判断。

持钥身份不证明自然人的唯一性、目的、偏好或理解。身份或单纯入场本身不自动证明接受某个目标、关系或请求；若获准的入场动作明确包含相应接受，则按世界声明的规则归因，不要求另设确认步骤。

### I4 Runtime 不冒充用户或外部 Agent

Runtime 可以按世界已经提交的规则执行系统行为，但不能把系统行为伪装成某个离线用户或 Agent 的新决定。模型推理、私人记忆、未提交意图、私人运行预算和停止条件由外部宿主保留，不属于 Runtime 权威状态。

世界资格与用户给宿主的授权是不同事实；工具可发现某项能力不等于当前推理请求获得了行动授权。世界运行已声明的过程也不等于获准启动新的私人推理。

## 持久性与一致性

### I5 已提交事实不依赖原会话存活

一旦世界变化被接受并提交，模型崩溃、客户端断线或响应丢失都不能自动撤销它。后续接续以权威状态和提交证据为准。

### I6 Runtime 管理的同一提交边界内不能留下半成品

属于同一次 Runtime 提交的状态变化、提交结果以及与该提交绑定的运行时效果必须一起成立或一起失败。验证、授权或规则失败不能留下局部世界事实。

### I7 不确定的传输结果不能靠猜测解决

没有收到响应不等于服务器没有提交。重试与恢复必须使用稳定的操作身份或持久提交证据；不能通过换一个新操作身份来掩盖未知结果。

## 观察、隔离与通用性

### I8 派生观察与表现不能创造权威事实

视图、缓存、读取位置、通知、动画、模型总结和客户端文案都只能表达或派生世界事实，不能因为“看起来完成了”就写成业务完成。

### I9 世界实例是默认的状态作用域

通过受支持的 Runtime 接口，一个世界实例的普通行动只能影响该实例，除非未来明确设计跨实例机制。这个不变量描述运行语义，不等于当前实现已经提供针对恶意世界代码的安全沙箱。

### I10 Runtime 保持领域中立

地图、职业、好友、背包、任务、审批、投票规则等都不能因为某个示例或测试先使用，就成为全部世界的硬编码前提。

中立性也覆盖参与目的、关系和体验：Runtime 不预设参与者有共同目标、必须合作、接受任务或拥有一致理解，不以协作者、冒险者或玩家等用途定义底层身份。具体世界仍可声明自己的角色、目标与约束；合法行动以该世界的明确规则和授权判断，Runtime 不额外强加共同目标。I2 不要求所有行动都采用请求／同意／确认流程。

### I11 声明的守恒与资源边界不能由消费者绕过

某世界声明守恒的材料、数量、容量、能量或预算，只能按该世界明确机制转移、消费、生成或释放。发现、定义发表、来源引用、表现、重试与恢复不能复制资源，不能用虚拟材料替代真实来源，也不能因客户端状态重置恢复已消耗预算。

世界可声明来源、汇、奖励或其他非守恒机制，但必须由同一规则与提交边界执行；通用内核不预设所有领域采用同一种物理守恒模型。

### I12 消费者可替换，事实与控制归属不改变

更换 Agent 宿主、模型、人类前端或呈现方式，不改变同一身份的世界档案、合法行动、已经提交的后果和原未知操作的恢复责任。不同消费者可读取不同的获准投影，但投影差异不能产生相互冲突的权威事实。

收回私人运行或行动控制必须阻止未来尚未执行的受托行动；已提交后果不因此回滚，尚不确定的原操作仍须依原证据恢复。某个 reference adapter 的入场、画面或会话形式不成为全部世界的参与前提。

## 与流程规则的区别

“测试不能偷偷改规格”“未决事项不能伪装成已完成”属于仓库治理规则，记录在 [BASELINE](BASELINE.md) 与 [AGENTS](../AGENTS.md)，不混入系统不变量本身。
