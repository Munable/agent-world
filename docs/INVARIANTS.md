# L2：系统不变量

复核：2026-09-27。本文只记录 **无论采用什么 API、数据库、界面或模块拆分，都不能被实现便利默默破坏的性质**。产品为什么存在见 [产品目标](../PRODUCT_POSITIONING.md)；具体对象见 [领域模型](DOMAIN_MODEL.md)。

## 权威与意愿

1. **Runtime 不从自然语言自行推断权威结论。** 文本可以作为消息、说明或证据字段保存，但文本本身不能自动产生确认、授权、任务完成或裁决。
2. **一个主体不能仅靠自己的声明制造另一个主体的意愿或行为事实。** 另一主体的确认、决定或提交必须来自获准的结构化操作，或来自预先定义、可验证的委托／第三方规则。
3. **身份验证与领域授权是两件事。** 证明“你是谁”不自动证明“你能做这件事”；各世界仍需按自身规则判断资格。
4. **用户持有底层身份。** 客户端和世界使用用户提供的凭据接入；当前 universe 范围令牌只是尚未完成跨世界验证的实现状态，不能升级为产品原则。

## 运行与持久性

5. **Agent 始终在 Runtime 外部运行。** Runtime 不托管模型推理、不保存私人推理上下文，也不在主体离线时伪装成该主体继续作决定。
6. **被接受并提交的世界变化不依赖原会话继续存在。** 模型崩溃、客户端断线或响应丢失不能自动撤销已经原子提交的世界事实。
7. **传输结果、回执、读取进度和业务完成彼此不等价。** HTTP/MCP 成功、operation receipt、event cursor、view checkpoint 都不能凭名称自动升级为“对方已确认”或“整个事项已完成”。
8. **当前权威事实与可重建表现分离。** 客户端缓存、动画、文本总结、读取标记和表现事件可以反映世界，但不能创造或改写服务端业务事实。

## 通用性与边界
9. **Runtime 不携带固定领域玩法。** 职业、地图、好友、任务、审批、仲裁票数等只能由具体世界或明确可选能力定义，不能因某个消费者存在就成为全部世界的必选对象。
10. **未决机制保持未决。** 实现尚未提供第三方／群众公裁、跨世界身份等能力时，应明确记录缺口，而不是删除需求、伪造完成或用当前实现反向定义规则。
11. **验证可以推翻假设，但不能静默改写规则。** 测试失败可能说明实现错误、合同含糊、测试假设错误或上层设计本身有问题；任何 L1-L4 的语义修改都必须显式发生。

这些不变量约束后续的 [行为合同](FOUNDATION.md)、[技术架构](ARCHITECTURE.md) 与具体实现；如果它们彼此冲突，应先把冲突写清楚，再决定修改哪一层。
