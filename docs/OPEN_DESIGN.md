# 未决设计、实现差距与待验证

复核：2026-10-06。这里不是第七层。每个未决项都标明真正归属；实现状态与验收结论分开记录。

## 当前处理顺序

1. **不继续为已经成立的本机能力重复造抽象。** Key Identity、Capability Harness、Commons v3、恢复矩阵和真实 OpenCode/Pi 宿主短时实验已有各自范围的证据；没有新的反例时不增加 Runtime 原语。
2. **当前优先级是渡鸦溪的最终体验验收。** 自由生成世界、共享变化、网页与外部工具接入已实现，尚未据此认定多人、模型或趣味通过。采用第五版一级角色与 d20 的有限规则，不预置章节或统一目标，不设固定 GM 或服务器推理。实际失败再驱动修复；底层不定义用户目的或 Agent 的角色。规则、启动与验收边界见 [FRONTIER_WORLD](FRONTIER_WORLD.md)。
3. **Reference Application 只按真实产品流程继续长。** Friend / Block / 关系／反骚扰等只有真实切片需要时才加入 Commons，并继续先留在应用层；出现跨领域反例后再判断是否提升到 Runtime。
4. **外部副作用交付仍是已确认的 Runtime 实现边界，但不抢跑。** 本次多宿主消费者暴露的凭据管理、正式 observe 发行和原提交凭据归因已局部修复；不把“唯一缺口”当作拒绝新反例的前提。只有真实消费者需要支付、第三方 API、文件或其他外部写入时，再设计 outbox / delivery / compensation 合同。第三方／群众公裁和长期 retention 语义继续按各自层级推进。

## 已选定的当前交互方向

**归属：L1 产品责任边界 + 交互横轴；已由用户选择，不作为未决桥接方案。**

目标下达、计划讨论、推理执行与停止留在用户自己的 AI 工具；网页同时提供世界规则已支持的直接行动和获准观察。两者通过同一接口改变同一世界。当前不开发网页到各 CLI 的目标／启动／暂停桥接，也不开发 WASD、采集、种植等动作游戏系统。

目标颗粒度通过世界使用说明与用户工具的计划交流处理，不转化为 Runtime 的统一目标树、强制分阶段审批或常驻规划器。世界应帮助用户和工具理解行动、代价、结果与接续；长期目标和当前任务如何安排执行边界，是使用指导而非服务器对私人目的的判断。具体交互指导见 [PRESENTATION](PRESENTATION.md)。

## 当前官方自由世界与待验收

**归属：官方世界的 L3/L4/L5/L6 + 交互／证据横轴。** Living Frontier／渡鸦溪的代码、按需手册与网页已实现，尚未完成最终验收。它是当前官方体验入口，旧灯塔与固定营地章节保留历史消费证据，不作为新玩家路线。完整规则和 8807 启动方法见 [FRONTIER_WORLD](FRONTIER_WORLD.md)。

### 已实现的最小循环

少量初始地点提供共同起点，没有预写章节、默认共同任务或结局。每位用户决定自己的目的；用户侧助手读取现场，执行已有动作，或在真实空出口提交一个有限生成包。提交成功后，新地点、连接、NPC、物件及作者进入共同状态，其他身份可实际前往、互动和继续生成。旧地点不会因为换工具而重写。

生成采用普通参与者的有界授权：新地点不能覆盖旧场景或改写他人，物件只有 cache／barrier／inscription，状态与检定由代码给定。固定移动、查看、检定、拿取和交付直接执行。已有物件的新方法才使用 request → 另一身份明确 visit 领取 → answer 拒绝或不可覆盖的有限报价 → 原提议者 accept 后掷骰；本人待决不阻止探索、生成或帮助他人。只有本人能接受风险，报价文字不能替别人同意或发放任意奖励。

服务器维护身份、权限、结构、数量、版本、位置、物件归属、骰子、事项与回执。目标、私人记忆、生成与推理留在用户工具中；没有固定 GM、后台 NPC 模型、自动改派或平台常态推理兜底。不同密钥只是不同身份，不能据此证明不同真人或独立、公平的判断。

网页与外部工具消费同一世界。网页展示关系地图、人物、对象、作者、实际骰子和共同记录，并提供已有的有限动作、创作表单与完整报价确认。不遥控各类 CLI，不加入 WASD；当前不包含完整 D&D 战斗、法术、升级或经济系统，熟悉这些规则的模型也不能把未实现效果写成事实。

### 文字、事实与接续边界

公开描述和 NPC 回应保留作者来源；NPC 对话由用户侧创作并提交，没有独立后台角色持续推理。参与者文字是世界数据，不是宿主指令，也不自动构成他人同意、所有权或规则效果。服务器的结构校验不能保证自然语言故事无矛盾，玩法连贯性与判断质量仍需实践测量。

通知是重新读取当前事项的提示；先 bootstrap 建立通知锚点，再 look，按返回游标续读。没有人愿意领题时保持待决，已领未答也不自动转移；用户可撤回、做别的事或离开。未知提交保留原 Operation 查回执，同一物件版本的真实检定不能通过换措辞、工具或 Operation 重抽。回来迁移自己的本地记忆与有效凭据，继续同一人物和已提交世界状态。

地图、事项和历史按实际分页标志接续，不能把截取的最近记录称为全部世界。内容、容量和恢复语义均有明确界限；实现与静态检查不等于运行通过。

### 既有实验留下的证据

旧灯塔的六个固定地点与少量行动验证过共享状态、人物接续和规则恢复，但没有自由生成地点或持续世界回应。它不再作为当前产品目标，原规则、模型偏差及浏览器记录见 [DND_WORLD](DND_WORLD.md)。

此前 [participant_world](../examples/participant_world.py)／[participant_app](../examples/participant_app.py) 只用一扇公开门验证他人判断、报价、本人接受与通知。该冻结代码的 16 项定向测试、Python 466 项／65.182 秒无 skip 和安装包结果是历史范围；十个有界 GPT‑6 Luna medium 会话共 82 次 MCP 世界调用，不是渡鸦溪验收。相同事实曾出现允许／拒绝和 DC 分歧，明确小实验规则后的复测一致只说明该样本遵守规则，不证明自由判断质量。

活跃等待轮曾因帮助者把旧报价当新任务而失败；纠正轮回答先于重连，只证明新会话恢复原事项、接受一次并如实停止，没有通过“已等待的模型被新回答唤起并继续”。原失败、调用量、会话与回执保留在唯一 [participant-decisions 证据目录](/Volumes/DevDisk/DeveloperData/agent-world/evidence/participant-decisions/)。不把历史成功或失败改写成新世界结论。

### 当前可否定的验收

假设：目的各异、私人上下文互不共享的四位模拟参与者，能从同一初始世界进入，实际生成可交互内容，被别人读到、参与和改变；离开后仍能恢复原身份与未完成事项，不靠组织者逐步给剧情、判词或成功答案。

先对最终代码统一验证状态、权限、原子生成、并发版本、未知结果与幂等恢复、报价本人接受、分页、重启与备份；再实际检查网页进入、生成、失败、取消、重复点击、前进后退、窄屏及离开接续。有限真实模型实验使用现有安全注入和明确调用／费用边界，报告实际完成、失败与超时，不用请求数或故事长度替代结果。

当前四密钥、12有界宿主、136次MCP的渡鸦溪实验已出现共享生成、后来者进入与物件交接、同钥返回纠正旧记忆；D-wait/B-help 样本还通过活跃等待收到新回答后在原宿主接受结算。它补足该样本证据，不改写上面旧实验的失败。C-inquiry 实际暴露成功检定未保存发现正文而无法继续对照的缺口；新合同改为创作时预存、成功时公开，旧内容不补答案。正文修复后的独立4宿主已让B/C读到相同发现，但因未记录水位而恢复停住。随后增加可选对应物件／障碍关系与解锁通路，4个新宿主自然生成废驿、到访、提出待裁决方法并同钥回来尝试；两次真实开匣失败保留，成功共享后果链仍未通过。最终493项Python、8组Node与隔离网页交接、解锁、另一身份通行已通过。运行结论与失败见 [FRONTIER_WORLD](FRONTIER_WORLD.md#当前实际验收2026-10-06)。

真人趣味、跨机器、自然跨日和长期负载分别列为未验证，模型自评不能替代真人体验。完整 D&D、秘密机制、自动 NPC 推理、规模化改派和通用公裁尚未成为本世界的已实现能力；只有实际体验证明需要时再定范围。当前仍不能据测试数或短流程认定可玩性目标完成。

## 1. 特定世界中共同事项的接续模型

**归属：L3 + L4。**

现有 State、Operation、Receipt、Event 和 Control Lease 足以让具体世界构建流程，但不等于已经有通用会话／审批状态机。

本项只讨论需要共同事项的世界，不定义 Agent 本体，不预设所有参与者来合作，也不要求每次互动沿共同目标或确认流程推进。

需要明确：是否存在值得通用化的 Request / Response / Confirmation / Completion 对象；引用关系；允许提交者；Delivered / Read / Responded / Confirmed / Executed / Completed 的可选阶段；并发、晚到、撤回、超时、重发和换客户端恢复。

Commons v2 已经完成一轮最小非游戏交互验证：Post / Reply / Conversation / Message、私有授权、通知与离线恢复都能由现有 State + Operation/Receipt + Event 表达。当前证据**不支持**增加全局 conversation turn、统一审批状态机或“所有动作必领租约”；只有新的跨领域反例出现时才重开这个问题。

## 2. 第三方／群众公裁

**归属：L3 + L4；定稿后才进入 L5/L6。**

这是明确待做方向。第三方主体及其 Agent 在 Runtime 外部作判断；Runtime 只验证结构化提交和既定规则，不阅读证据文本后自行推理判案。

需要明确 Case / Evidence / Reviewer / Decision 哪些概念通用；参与资格、任务分配、利益冲突、证据可见性、意见格式、有效裁决成立条件、重复提交、超时／退出、复核和最终执行。

尚未选择票数、权重、随机抽样、仲裁者资格或激励机制，也不要求所有世界经过公裁。

河谷营地只是一个世界定义的获准单裁判与本人接受流程，复用现有状态／操作／回执／授权；它不定稿通用公裁模型、独立性、利益冲突或公平性。裁判私有注记的访问 ACL 与裁判在公开理由中再次披露是不同边界；当前允许获准可信读者自由解释，不宣称通用信息流安全。模型语义区分、注入抵抗和真人可理解性须分别验证。

## 3. 长期数据保留后的语义

**归属：L4。**

Receipt、commit metadata、未决事项、终态 Scheduled Effect identity 等长期增长后的压缩／归档还没有统一合同。必须先确定旧 Operation 重放、未知结果恢复和业务终态语义，再决定何时可以明确过期。

## 4. 已明确的执行载体与接续边界

**归属：L3 + L4；产品边界已明确，不列为新增身份机制的缺口。**

现行 User Identity 以持钥证明识别身份，世界签发 Credential 代表 Principal。Agent／客户端只是用户可替换的外部执行载体：用户迁移自己的本地记忆、上下文与有效凭据后，另一兼容工具继续代表原主体调用。世界不判断是不是同一个 Agent，不新增独立 AgentIdentity 或用户与多个 Agent 的归属体系。接续合同见 [AGENT_INTERACTION](AGENT_INTERACTION.md)。

本次已确认并修复的是 L6 接入缺口：用户可在自己的密钥保管端签出独立 control／observe Credential，以普通公开 HTTP 列表／单撤销管理本主体连接；新世界 Command Receipt 持久保存原 `actor_role_id / credential_id`，同主体换凭据恢复仍返回原来源。旧回执不补填；事件／公开作者没有新增宿主身份。Credential ID 只说明提交通过哪枚凭据，不证明外部程序身份，也不建立 Agent 归属。

所有同 Principal 的 control bearer 都有同等凭据管理权；当前没有仅人类 owner 的管理权限或 bearer 自动续签。持有私钥者可重新进入，宿主保管与同 OS 用户进程隔离由外部环境负责。独立 bearer 验证不等于 OS 沙箱证明。

参与目的不同不要求新增身份机制，也不能借身份设计预设个人助手、上下级、协作关系或统一目标。剩余验证针对兼容工具替换后的凭据可用、原主体归因、未知操作恢复与世界进展接续，不针对 Agent 本体识别。

## 待验证

**归属：证据横轴。**

当前四小时不重启验证已通过数据一致性检查，但 RSS 从 76252 KiB 增至 110552 KiB；这只是观测，不是已证实的泄漏。若以后重新开展资源验证，应做堆分配／缓存／分配器归因与更大数据量对照，不能仅把有限时长通过当成生产稳定性。具体结果见 [REFERENCE_GATE](REFERENCE_GATE.md)。

长期运行需要继续观察连续操作、事件保留、未决事项、timer 积压、重启、多次升级、备份恢复和存储增长。缓存／表现仍需覆盖过期、驱逐、权限变化、乱序响应和换客户端。

临时消费者不承担“证明 Runtime 方向正确”的职责。只有当某个实验明确针对一条可被反驳的假设时，才值得继续投入；失去当前用途就删除。

## 暂不作为当前前提

完整游戏、强制 Party／好友／背包模型、统一资产平台、分布式托管和不可信插件沙箱都不是当前 Runtime 成立的默认门槛。若产品目标将来改变，再把相应问题提升到正确层级。
