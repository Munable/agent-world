# 未决设计、实现差距与待验证

更新：2026-09-27。这里不是第七层。每个未决项必须标明它真正影响的 L1-L6 或横向证据／表现位置；候选方案在决定前不具有现行合同地位。

## 待设计

### 1. 共同事项的接续语义

**归属：L3 领域模型 + L4 行为契约。**

现有结构化函数、事件、回执、活动足以让具体世界构建流程，但不等于 Runtime 已经拥有统一对话／审批状态机。

需要先明确：请求／事项对象是否值得形成通用概念；请求与回应怎样引用；Delivered、Read、Responded、Confirmed、Executed、Completed 如何区分；并发／晚到回应；撤回、超时、重新发起；换客户端后需要恢复哪些权威事实；通知保留期到达时未决事项如何继续。

先用最小非游戏交互列出提交者、对象 ID、结构化输入、状态变化和失败分支，再判断哪些模型或辅助合同真正通用。不要直接增加全局轮次、统一审批状态机或所有操作必领租约。

### 2. 第三方／群众公裁

**归属：L3 领域模型 + L4 行为契约；之后才进入 L5/L6。**

这是明确待做方向，不是“服务器无法理解自然语言所以忽略”。评审主体及其 Agent 在 Runtime 外部；服务器只验证结构化提交和既定规则，不读取证据文本后自行推理裁决。

待定：Case / Evidence / Reviewer / Decision 等哪些概念真正需要固化；参与资格与任务分配；利益冲突；证据可见性；意见格式；有效裁决的成立条件；重复提交；超时／退出；复核；最终结果怎样执行。

尚未选择票数、权重、仲裁者资格、随机抽样或激励机制。不能提前写成实现承诺，也不能强制所有世界经过公裁。

### 3. 数据保留后的语义

**归属：L4 行为契约。**

需按数据用途确定回执、commit metadata、未决事项、终态 timer ID 等的长期保留和恢复边界。当前 event/history 清理不约束数据库总大小；不能直接删除去重或恢复依据，导致旧 operation 再次执行。

先测长期增长、恢复和旧 ID 行为，再决定压缩、归档、明确过期拒绝等合同；不要先引入大型存储平台来掩盖语义没定。

## 明确的实现差距

| 项目 | 归属 | 已确定要求 | 当前状态 |
| --- | --- | --- | --- |
| 跨世界身份 | L6 相对 L1/L2 的缺口 | 用户持有跨世界通用的底层身份与档案，各世界另行授权。 | 当前 token 绑定 role + universe；独立部署统一验证未落地。不能仅删除 universe 隔离检查伪装完成。 |
| 凭据轮换结果恢复 | L4/L6 | 已经完成的轮换不能因为一次响应丢失而只能猜测结果。 | 当前丢响应仍需操作员处理。 |
| 通用共同事项辅助 | L3/L4 | 若抽象成 Runtime 能力，必须保持读取、回应、确认、执行、完成的语义差异。 | 尚未决定是否值得提取通用模型／接口。 |
| 第三方／群众公裁 | L3/L4 | 不能由争议一方或服务器自然语言推断单方面制造裁决事实。 | 领域模型、成立规则和执行合同均未定稿。 |

本整理分支已经复现并修复 managed-world legacy raw-state 的 schema／授权回退；它不再作为未完成项重复维护。范围见 [FOUNDATION](FOUNDATION.md) 与仓库审计。

## 待验证

**归属：验证证据横轴。**

长期运行需观察连续操作、事件保留、未决事项、timer 积压、重启、多次升级、备份恢复后的组合行为。加速循环不等于真实运行数月，固定脚本也不等于真实外部 Agent 行为。

缓存／表现需要继续检查过期、驱逐、权限变化、乱序响应和跨客户端恢复；通信需要覆盖外部 Agent 完全停止后重新进入，以及响应丢失后同 operation_id 恢复。

只对实际观察到的结果作结论。当前验证入口见 [REFERENCE_GATE](REFERENCE_GATE.md)。

## 暂不作为前提

完整游戏、通用规则引擎、强制 Party／好友／背包对象、不可信插件沙箱、分布式托管、统一资产平台都不是当前逻辑核对的先决条件。

外部系统副作用、动态群体频道等有真实消费者和失败案例后再决定所属模型／合同；不要把“也许以后有用”升级成 Runtime 必备抽象。

日常验证优先本地或可控机器；保留必要历史证据，但不复制多份路线图。
