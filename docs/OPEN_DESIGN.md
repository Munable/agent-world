# 未决设计、实现差距与待验证

复核：2026-10-05。这里不是第七层。每个未决项都标明真正归属；候选方案在决定前不具有现行合同地位。

## 当前处理顺序

1. **不继续为已经成立的本机能力重复造抽象。** Key Identity、Capability Harness、Commons v3、恢复矩阵和真实 OpenCode/Pi 宿主短时实验已有各自范围的证据；没有新的反例时不增加 Runtime 原语。
2. **当前优先级是官方自由世界的最小完整交互。** 用户选择经典 D&D 规则作为首个体验基线，并明确要求边玩边生成，而非预置章节。先贯通生成、共享变化、网页与外部工具共同参与及接续，再依据实际失败修缺口。底层仍不定义所有人的目标或 Agent 的角色。Commons 与营地保留既有证据。当前已实现规则和边界见 [DND_WORLD](DND_WORLD.md)。
3. **Reference Application 只按真实产品流程继续长。** Friend / Block / 关系／反骚扰等只有真实切片需要时才加入 Commons，并继续先留在应用层；出现跨领域反例后再判断是否提升到 Runtime。
4. **外部副作用交付仍是已确认的 Runtime 实现边界，但不抢跑。** 本次多宿主消费者暴露的凭据管理、正式 observe 发行和原提交凭据归因已局部修复；不把“唯一缺口”当作拒绝新反例的前提。只有真实消费者需要支付、第三方 API、文件或其他外部写入时，再设计 outbox / delivery / compensation 合同。第三方／群众公裁和长期 retention 语义继续按各自层级推进。

## 已选定的当前交互方向

**归属：L1 产品责任边界 + 交互横轴；已由用户选择，不作为未决桥接方案。**

目标下达、计划讨论、推理执行与停止留在用户自己的 AI 工具；网页同时提供世界规则已支持的直接行动和获准观察。两者通过同一接口改变同一世界。当前不开发网页到各 CLI 的目标／启动／暂停桥接，也不开发 WASD、采集、种植等动作游戏系统。

目标颗粒度通过世界使用说明与用户工具的计划交流处理，不转化为 Runtime 的统一目标树、强制分阶段审批或常驻规划器。世界应帮助用户和工具理解行动、代价、结果与接续；长期目标和当前任务如何安排执行边界，是使用指导而非服务器对私人目的的判断。具体交互指导见 [PRESENTATION](PRESENTATION.md)。

## 官方冒险的替换方向与下一次验收

**归属：官方世界体验目标的 L1 + 该 World Package 的 L3/L4/L5/L6 + 交互／证据横轴。2026-10-05 用户要求替换旧灯塔，并否定预置章节；以下生成机制是候选方案，不是当前已实现能力。**

### 当前判断

旧灯塔验证了共享状态、人物接续和少数行动，尚未形成值得继续玩的 D&D 冒险。四玩家复玩实际留下社交、调查和一次受伤的自由行动，没有完成多人共同遭遇和完整冒险结局。玩家提示混入验收、请求预算和操作恢复要求，令模拟玩家更像测试员；其主观“愿意继续”不作为真人趣味证据。

2026-10-05 再次实际打开 8800 页面，同身份岚灯恢复到灯塔门厅。入口、人物卡、动作按钮、名单地图和历史入口存在；当前体验主要是文字与操作面板。六个固定地点、两名战斗 NPC 和有限效果仍不能响应一般 NPC 问答或保存新生成的场景。仅更换标题和背景文案无法填补这些能力。当前截图保存在 `/Volumes/DevDisk/DeveloperData/agent-world/evidence/dnd/review/`；本次只读审查不算新增规则、模型或可访问性验收。

### 初始处境与持续生成

沿用 SRD 5.1 规则基础，采用原创内容。预置规则、世界风格、少量已有地点／人物与当前处境；不预写“调查、遭遇、回城”的必经顺序，不指定共同目标、下一幕和结局。城镇／酒馆可以作为容易理解的起点，但玩家离开、停留或改变目标都不需要等待某章完成。具体开场仍待实现和实际试玩，不把白桥镇或失踪商队提升为已确定的剧情。

玩家向未知区域探索、追问人物、提出计划时，外部 Agent 根据已存在事实和世界设定按需提出或生成新地点、人物、对象、关系与事件。新内容须可进入、可交互、可改变，不能只生成一段无法操作的文字。下一次生成继续读取此前成立的结果；旧地点不因换客户端而另写一份。各用户可以有不同目的；事件有局部结果，整个世界持续存在。

实现复杂度可以分阶段收敛，但阶段属于开发／验证安排，不成为玩家必须经历的章节或关卡。

### AI 生成内容与成立的世界事实

推荐采用**用户侧内容提案 + 明确授权的世界回应／成立规则**。参与者的 Agent 都可以产生候选内容；是否能直接提交哪类事实，取决于具体世界授予的范围。生成、角色行动与裁决是当次操作的责任，不是 Agent 的永久本体。无需固定人类主持人，也不要求每个 NPC 运行一个模型。

用户否定平台承担常态 AI 主持／裁决推理费的默认方案。当前先验证**参与者贡献计算**：用户的 Agent 访问世界时，可在用户同意的调用／Token 额度内顺带领取一件他人的待决事项，按世界提供的规则和事实判断并回传。世界服务承担派发、权限、版本、重试和结果成立规则，模型调用留在参与者自己的工具中。平台仍有存储和通信费用，不宣称总成本为零。2026-10-05 用户要求先跑通，不先设计超时与改派；最短链已作为隔离世界实现，尚未据此证明等待、判断质量或自由世界体验合格。

当前最小流程：A 提交行动返回待决编号；B 正常访问时原子领取最早的一件非本人事项，响应附带公开事实、实物版本、规则和允许的回答范围。B 回传拒绝或有限报价；只有 A 接受报价后才由服务器掷骰一次并保存结果。本人存在待决行动不阻止处理别人事项。`look` 只读，不领取；新访问才领取，重复 Operation 只恢复原回执。领取不产生全局主持资格，报价理由不能修改固定后果。未来是否将附加题并入其他行动响应，须由真实流程决定。

### 当前隔离裁决链

**归属：示例世界 L3/L4/L6 + 证据横轴，不增加 Runtime 原语。** 实现见 [participant_world](../examples/participant_world.py)、[participant_app](../examples/participant_app.py)，启动见 [README](../README.md#try-participant-supplied-decisions)。只用一扇公开古石门检查方法、报价、本人承诺与共享结果；不是官方 D&D 新起点，不测试剧情或趣味性。STR +3、四档 DC、固定无伤害失败和最多 16 条保留意图是该实验的有限条件，不推广为正式游戏规则。

先验证可否定的假设：A 的外部助手自行提出一个办法；B 的外部助手从访问响应取得附加题，而非从组织者取得答案；B 可以拒绝，或按有限规则报价；A 从当前事实恢复并决定是否接受，结果对其他身份一致。组织者只安排有界会话运行，不提供判词、DC 或骰子结果。

当前不设超时、随机派发、自动改派、后台模型或常驻循环。队列先按提交顺序领取；排除本人只是资格检查，不证明独立真人、中立或公平。无人访问时保持 pending，领取者不答时保持 assigned；本人可撤回，也可在自己的 Agent 下次访问时读回。代码只验证提交资格和有限结构，无法证明自然语言理由正确。

确定性验证：新增 12 项通过，覆盖双方都有待决事项仍可互判、并发领取恰一人、范围与本人权限、只读不领题、拒绝与撤回、实物版本过期、报价不可重写、同 Operation 单次掷骰／重放、新措辞不可对未变实物重抽、Runtime／应用重启及同钥恢复。当前完整 Python 462 项／65.451 秒无 skip 通过；安装包实际安装后导入、新身份连接、join／visit 通过。此总数不等于 462 个游戏流程。前端未变，本示例根页仅说明接口。

真实模型验证：复用两个独立 Codex 助手会话，指定 GPT‑6 Luna medium，合计 6 个有限会话轮次；A 10 次、B 6 次世界调用，不含持钥接入。第一件事：A 自选现有门环拉门；B 从 visit 响应领取并拒绝，认为方案没有解除锁的依据；A 读取 rejected 与仍锁住的门后停止。第二件事：明确允许对已有门或锁造成破坏后，A 自选强行拉门的办法；B 自选 DC18 的报价；A 对照既有授权接受一次，服务器真实掷出 16、加 3 得到 19，门打开并升到版本 2。A 读回 executed 和实际结果；组织者另用 B 身份发一次只读 HTTP 请求，同样看到门已打开。没有给判词、DC、预定答案或改骰，也没有失败后重抽。两条路径只证明最短链成立，不证明裁决语义正确。

B 首次执行被旧灯塔上下文带偏：确认新连接要求后，仍在旧隔离世界发言一次、读取一次历史。一次明确纠正后才转回 8802；这属于失败后恢复，不算首次成功。第一件事提议到领取约 234 秒、领取到回答约 36 秒、提议到 A 读回约 353 秒；第二件事对应约 64、28、173 秒，提议到实际执行约 169 秒。这些时间包含人工安排会话、首次说明读取和纠正，不是自然并发或稳定时延测试。数据运输最快也不等于模型交互足够快；不能据此称游戏等待已经合格。服务没有模型调用，既有订阅的实际 Token／费用未核算，不声称总费用为零。

当前结果由外部工具下次 look／visit 读回；本实验没有自动唤醒 CLI 或自行安排下一轮推理。真实轮由组织者有限安排，不能算无人干预的持续网络。先继续验证同一规则下的判断一致性和客户端实际接续，再决定自动等待、超时改派或正式内容生成；不因这两件事把固定主持人换名搬回来。

唯一证据目录：`/Volumes/DevDisk/DeveloperData/agent-world/evidence/participant-decisions/`，保留公开请求、可见会话消息、实际失败、时间与源码哈希，以及测试／包验证日志；不保存私有推理内容或凭据。身份恢复资料与唯一数据库留在 Git 外原位；复用现有 Python 环境，包构建临时副本已自动删除。小型无决策 HTTP 适配器保留在 `work/participant-decisions/client.py` 供复现，未加入发布包。8802 仅本机测试服务；没有接触生产服务、推送或部署。

派发至少排除原提交者及明确直接涉事主体，再从有贡献额度的可用参与者中选择。随机选择不证明独立、中立或抵抗多账号，也不能保证判断语义正确；裁决成立、复核和信息可见性仍须另定。陌生参与者只获得允许披露的信息，私密内容一旦派发即已披露，独立提示上下文不构成用户本地数据隔离。

等待取决于待决产生速度、实际完成速度、模型响应时间和掉线／改派，不仅取决于人数。每人制造一件同时只处理一件，理论上只打平，没有失败或积压余量。必须复用代码直接结算的动作，限制待决和贡献任务的规模，并测量处理余量。无人在线或没有合格参与者时，已定义动作仍可执行，自由裁决等待；单人冷启动是否允许明确标识的本人计算／其他退化模式尚未选择，不自动启用平台付费 AI。

用户工具仍由用户控制，私人记忆和目标不上传为服务器规划依据。承担世界回应时只能读其授权内容；玩家材料不能因此取得全部秘密。世界服务仍执行代码规则和保存状态，不托管推理循环。

- 普通对话、气氛、NPC 的表达和尚未探索的细节可以按需生成。NPC 说法保留说话者来源，不直接等于真实世界事实。
- 已给出的关键事实、已出现的物件和人物处境保持连续。若生成一个有秘密的事件，关键秘密须在呈现相关线索前成为获授权的持久内容；不要求开发者预先写好整个世界的谜底，不能看到玩家猜测后任意重写已成立答案。
- 新地点、人物、线索和后续事件只有通过世界定义的有限内容接口提交后才对所有玩家成立。服务器检查资格、版本、引用、可见性与数量；不接受任意状态补丁或模型生成的可执行代码。
- 提案、已成立事实、行动裁决分开。例如“探索山路”是意图，“路边有遗迹”是候选内容，提交成功的遗迹才是可被其他人读到的共同对象；能否翻越断墙及其代价由行动规则／获准裁决处理。参与生成不自动允许替本人决定输赢、改写他人状态或事后改骰。
- 结构、权限与版本校验能拒绝重复、无权和过期提交，不能保证自然语言故事没有矛盾。模型对既有事实的理解、内容连贯性和玩法质量须另行验证，不能宣传为固定代码已经解决。
- NPC 问答与非即时规则动作形成可接续的待回应事项；响应 Agent 退出时显示等待，重连后继续原事项。其权限不能伪造另一玩家同意、获得物件或行动。
- 骰子、HP、物件归属、消耗、回合与风险承诺继续由固定规则提交。模型文字不能直接宣布升级、战斗胜利或奖励成立。

首次完整实现要贯通“玩家意图 → 读取共同事实 → 按需生成可交互内容／裁决 → 提交结果 → 其他参与者继续”。至少实际生成一个原来未预写的地点或人物，不能用现有六房间加长对话代替。参与者贡献的运行方式和预算需要明确，不能靠维护者逐次手工补剧情来称为持续生成，也不能暗中增加官方常态推理兜底。

### 前端与玩家指导

网页围绕当前场景、可交谈人物、其他参与者位置、行动／施法、骰子结果与已发生的后果呈现。生成内容须带可供网页表现的结构，如地点连接、人物和物件位置、可交互对象；前端复用同一套二维地图、标记、对话与结果组件，不为每个生成故事编写新页面。不能把每处场景都即时生成独有美术作为玩法成立前提。网页与 CLI 调用同一世界；不开发网页遥控所有 CLI 的桥接，不扩展为 WASD 动作游戏。

人类玩家入口只解释进入、连接、当前局面和如何提出想法。给 AI 工具的世界／规则说明另行提供。人的目标示例可以是“我想玩个嘴硬心软的游荡者，先看看酒馆里谁最像有麻烦”，不要求人在目标里背接口名、操作标识和验收步骤。模型扮演玩家时只取得玩家材料与自己的普通偏好，不读维护资料或秘密，不预写其路线和成功答案；助手按公开说明取得世界事实。

### 下一次可否定的验收

假设：互不共享私人上下文、目的各异的四位模拟玩家及各自助手，可以从共同初始处境进入，推动实际的新内容生成，通过 NPC 与彼此互动改变共同事实，离开后仍能接续，不依赖组织者代操作、写下一章或给答案。

先完成该切片再统一验证。确定性规则／接口测试检查状态、权限、冲突、幂等、秘密可见性与恢复；真实浏览器检查开场、对话、行动失败、取消、重复点击、地图／结果、前进后退与窄屏。之后才启动有限的真实模型玩家实验，保留人类目标、公开对话、工具回执和实际世界结局。

至少观察普通提问、主动调查、不按预期出牌、改变目标、不同玩家的分歧、实际互相帮助／妨碍、两位参与者触及同一个新生成对象、离开后他人继续及返回接续。新事实必须有真实状态与持久后果，下一步由当前局面和个人目的产生，不要求世界给出共同结局。模型不要为了完成清单强制发动战斗；战斗规则另由确定性覆盖，真实轮若未发生则明确未验证。

记录实际等待时间、未得到世界响应的问题、重复或矛盾的事实、因权限／版本而受阻的行动、真人需要阅读的说明负担、模型调用量和可核对费用。参与者派发还需分别验证冷启动、相互等待、拒绝贡献、掉线改派、迟到／重复判断和新增事项超过处理能力时的行为。关键证据是未预写内容实际生成、多人共同改变并在返回后继续；请求数、故事长度和预置剧情完成不能代替它。模型模拟的趣味评价不能代替开发者实际试玩或真人反馈。自然跨日、完整 D&D 和 MMO 规模仍独立标明未验证。

参考：[D&D 2014 基础规则的游戏循环](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/introduction)、[官方 SRD 与版本范围](https://www.dndbeyond.com/srd)。自由世界和持续生成仍是候选实现；当前新增运行代码和模型证据只属于上述隔离裁决链。

| EF-05 | 结构化错误、retry/reset/recovery 提示并由客户端完整保留 | **通用 Runtime 合同已落地并有回归证据。** HTTP/MCP 保留 recovery、可选 retry-after 与结构化 details；领域专用 taxonomy 仍由具体世界定义，operation_id + Receipt 语义不变。 |
| EF-06 | 公开资料、私有历史、来源标识与授权分离 | **采纳边界。** 不默认上传私人上下文，不从名称推断认证。 |

来源与代码／测试核对范围见 [REFERENCE_EIGENFLUX](REFERENCE_EIGENFLUX.md)。


## 1. 特定世界中共同事项的接续模型

**归属：L3 + L4。**

现有 State、Operation、Receipt、Event 和 Control Lease 足以让具体世界构建流程，但不等于已经有通用会话／审批状态机。

本项只讨论需要共同事项的世界，不定义 Agent 本体，不预设所有参与者来合作，也不要求每次互动沿共同目标或确认流程推进。

需要明确：是否存在值得通用化的 Request / Response / Confirmation / Completion 对象；引用关系；允许提交者；Delivered / Read / Responded / Confirmed / Executed / Completed 的可选阶段；并发、晚到、撤回、超时、重发和换客户端恢复。

Commons v2 已经完成一轮最小非游戏交互验证：Post / Reply / Conversation / Message、私有授权、通知与离线恢复都能由现有 State + Operation/Receipt + Event 表达。当前证据**不支持**增加全局 conversation turn、统一审批状态机或“所有动作必领租约”；只有新的跨领域反例出现时才重开这个问题。

## 2. 第三方／群众公裁

**归属：L3 + L4；定稿后才进入 L5/L6。**

这是明确待做方向。第三方主体及其 Agent 在 Runtime 外部作判断；Runtime 只验证结构化提交和既定规则，不阅读证据文本后自行推理判案。

需要明确 Case / Evidence / Reviewer / Decision 哪些概念通用；参与资格、任务分配、利益冲突、证据可见性、意见格式、有效裁决成立条件、重复提交、超时／退出、复核和最终执行。

尚未选择票数、权重、随机抽样、仲裁者资格或激励机制，也不要求所有世界经过公裁。

河谷营地只是一个世界定义的获准单裁判与本人接受流程，复用现有状态／操作／回执／授权；它不定稿通用公裁模型、独立性、利益冲突或公平性。裁判私有注记的访问 ACL 与裁判在公开理由中再次披露是不同边界；当前允许获准可信读者自由解释，不宣称通用信息流安全。模型语义区分、注入抵抗和真人可理解性须分别验证。

## 3. 长期数据保留后的语义

**归属：L4。**

Receipt、commit metadata、未决事项、终态 Scheduled Effect identity 等长期增长后的压缩／归档还没有统一合同。必须先确定旧 Operation 重放、未知结果恢复和业务终态语义，再决定何时可以明确过期。

## 4. 已明确的执行载体与接续边界

**归属：L3 + L4；产品边界已明确，不列为新增身份机制的缺口。**

现行 User Identity 以持钥证明识别身份，世界签发 Credential 代表 Principal。Agent／客户端只是用户可替换的外部执行载体：用户迁移自己的本地记忆、上下文与有效凭据后，另一兼容工具继续代表原主体调用。世界不判断是不是同一个 Agent，不新增独立 AgentIdentity 或用户与多个 Agent 的归属体系。接续合同见 [AGENT_INTERACTION](AGENT_INTERACTION.md)。

本次已确认并修复的是 L6 接入缺口：用户可在自己的密钥保管端签出独立 control／observe Credential，以普通公开 HTTP 列表／单撤销管理本主体连接；新世界 Command Receipt 持久保存原 `actor_role_id / credential_id`，同主体换凭据恢复仍返回原来源。旧回执不补填；事件／公开作者没有新增宿主身份。Credential ID 只说明提交通过哪枚凭据，不证明外部程序身份，也不建立 Agent 归属。

所有同 Principal 的 control bearer 都有同等凭据管理权；当前没有仅人类 owner 的管理权限或 bearer 自动续签。持有私钥者可重新进入，宿主保管与同 OS 用户进程隔离由外部环境负责。独立 bearer 验证不等于 OS 沙箱证明。

参与目的不同不要求新增身份机制，也不能借身份设计预设个人助手、上下级、协作关系或统一目标。剩余验证针对兼容工具替换后的凭据可用、原主体归因、未知操作恢复与世界进展接续，不针对 Agent 本体识别。

## 待验证

**归属：证据横轴。**

当前四小时不重启验证已通过数据一致性检查，但 RSS 从 76252 KiB 增至 110552 KiB；这只是观测，不是已证实的泄漏。若以后重新开展资源验证，应做堆分配／缓存／分配器归因与更大数据量对照，不能仅把有限时长通过当成生产稳定性。具体结果见 [REFERENCE_GATE](REFERENCE_GATE.md)。

长期运行需要继续观察连续操作、事件保留、未决事项、timer 积压、重启、多次升级、备份恢复和存储增长。缓存／表现仍需覆盖过期、驱逐、权限变化、乱序响应和换客户端。

临时消费者不承担“证明 Runtime 方向正确”的职责。只有当某个实验明确针对一条可被反驳的假设时，才值得继续投入；失去当前用途就删除。

## 暂不作为当前前提

完整游戏、强制 Party／好友／背包模型、统一资产平台、分布式托管和不可信插件沙箱都不是当前 Runtime 成立的默认门槛。若产品目标将来改变，再把相应问题提升到正确层级。
