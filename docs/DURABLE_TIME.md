# L4：持久定时事项合同

复核：2026-09-27。Scheduled Effect 是世界已提交、将在未来由明确 System Actor 执行的事项。它不是后台 Agent、模型会话，也不是替离线用户重新作决定。

## 声明、调度与取消

世界必须预先声明可执行的定时处理规则及其输入、版本、授权和失败策略。普通外部调用者不能通过猜名字直接执行内部定时处理器。

调度或取消必须发生在获准的世界写入中，并与产生它的世界变化一起提交；创建动作回滚时，不应留下孤立定时事项。

调度者决定“未来要按这个规则执行”的意图在创建时已经提交。执行时使用明确的 System Actor 来源，并保留原始发起者／Operation 等必要 provenance，但不能把执行时刻伪装成用户又作了一次新决定。

世界规则决定谁可以创建、取消、查看定时事项，以及创建者之后失效时该事项是否仍应执行。

## 执行与原子性

到期执行必须重新检查当前世界版本、处理规则版本以及声明的执行授权。已经不适用于当前世界的旧事项不能被新代码静默重解释。

一次触发产生的 Runtime 管理状态、Receipt、通知、后续 Scheduled Effect 等必须形成一个原子提交。执行在提交前崩溃时可以重跑，但最终不能产生两套已经提交的数据库效果。

外部付款、网络写入和文件副作用不享受这层原子性，仍需独立交付合同。

## identity、重复与取消

Scheduled Effect identity 在 World Instance 内必须稳定。同一 identity 重复调度同一意图应当幂等；拿同一 identity 改成不同意图应冲突。已经完成或取消的 identity 不应被无意复活。

取消只有在取消提交先于触发提交时才阻止执行。取消已完成事项不能倒转已提交世界事实；触发中的事项也不能通过自我取消制造部分提交。

## 失败与重试

可重试失败必须回滚本次候选效果，再根据声明策略安排以后重试。授权／规则明确拒绝和未预期处理器故障应有可区分终态；错误详情不能泄露不应公开的内部数据。

重试必须有预算和延迟边界，单次调度 sweep 也必须有容量边界，避免一个立即重排的事项在同一循环里无限自激。

某个坏事项失败不应阻塞其他独立到期事项。

## 时间与晚到

due time 是执行不得早于的现实时间约束，不是虚构游戏时间或对话轮次。服务停机后恢复时，可以补执行已经过期的一次性事项，但不能伪造本来不存在的周期执行。

时钟回退／前跳和服务晚到都会影响实际触发时间；具体世界必须定义“晚到是否仍有业务意义”，Runtime 不承诺硬实时。

## 连续工作检查点

受信世界可另外声明连续工作检查点。检查点以稳定工作键和单调代次标识执行，不把每次服务器推进伪装成新的用户 Operation。当前待办、代次处理水位与最近一次准确终态结果必须和世界后果原子保存；同一代次已完成后不能再次执行。处理器可以在完成本代次的同一提交中安排下一代次，不能因此覆盖尚未完成的工作。

水位表示旧代已处理或取代，不证明全部成功计算；最新准确终态、当前任务状态与世界实际计算水位分别表达。连续工作的旧准确结果可以按明确策略过期；查询须区分“仍待执行”“已完成且结果可读”“已完成但准确结果已过期”。结果过期不能解释为从未执行，也不能重新执行旧代次。普通一次性 Scheduled Effect 与用户 Operation 的 identity 和原回执合同保持不变。

调度延迟只延后连续工作的实际完成，不自动丢弃已经保存的工作或补出墙钟间的虚构推进。世界需要说明其逻辑时间、局部失败、接续和停机行为；检查点不提供另一套私有游戏时间。

Shared Grove 每个公共逻辑轮只安排一个后继。正常运行的节拍锚定本轮实际打开时刻，下一轮不得早于锚点后一秒；本轮完成较晚时可以立即开始后继，不在每次完成后再额外等待一秒，也不按漏掉的墙钟时间生成多个补偿步。停机恢复把节拍单独重锚到恢复时刻，保留未结束轮的原始打开事实、目标逻辑步、事件截止和已完成域；已经结算的域不能因恢复再次推进。

观察历史维护不执行世界规则，也不能合并独立域的世界提交。流引用释放和 checkpoint 历史回收可以在同一有界维护事务内依次执行；回收失败时两者一并回滚，准确最新回执、用户 Operation、权威状态及已处理代次保持原合同。持续到期工作仍须获得有界回收机会，不能只在空闲时维护或因等待写锁耗尽计算预算而永久不前进。维护的期限是协作让出的预算，不能硬抢占 SQLite 提交或可信处理器。

宿主存储维护可独立执行 SQLite 官方 PASSIVE WAL 回填，保持 FULL 提交持久性。回填不推进世界、不占 Runtime 写锁，也不能在线强制终止读快照或删除 WAL。长读快照可能使回填不完整并增加 WAL；维护间隔不是硬时间或空间上限。维护线程正常或异常结束后，后续写连接恢复默认自动检查点；停机后已提交但未回填的 WAL 仍参与原数据库恢复。
