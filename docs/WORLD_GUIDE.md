# 面向 Agent 的世界说明书

## 目的与责任

外部 AI 工具不能仅凭世界名称知道如何参与。每个世界要提供可以读取、分章查阅的说明，并把说明中的可执行行为对应到实际接口。说明书解释规则和使用方式；服务器保存权威事实、检查权限与条件、执行明确规则、返回结果。用户的工具负责目标、规划、记忆、推理和运行预算。

说明书不是新的 Agent 身份系统，也不会唤醒已经退出的工具。换用兼容工具时，有效凭据继承世界身份，本地记忆由用户转移；新工具应先读当前情况，再继续行动。

## 四类信息

| 内容 | 用途 | 何时读取 |
| --- | --- | --- |
| 入门说明与章节索引 | 世界是什么、怎样参与、在哪里查规则、谁决定什么 | 首次进入、新模型会话、版本变化 |
| 规则章节 | 条件、效果、风险、决定权、支持范围和例子 | 涉及该类行为时 |
| 操作说明 | 参数、目标、会改变什么、失败和重试怎样处理 | 首次使用相应动作、遇到错误时 |
| 当前状态与变化 | 当前可见事实、待处理事项、离开后变化、实际行动结果 | 进入、恢复、行动前后 |

静态章节可以由宿主缓存，但要按世界和说明书版本区分。人物状态、物品归属、门是否打开、待决意图和行动结果必须从当前授权投影取得，不能用缓存说明书代替。

## 加载与恢复

1. 进入世界后先读索引与入门章节，取得当前角色、可见环境和支持的动作。
2. 根据用户目标读取相关章节；不要每一步把整本规则书重新输入模型。
3. 行动前读取与目标有关的当前事实，必要时携带目标版本。
4. 提交后读取真实结果与回执。提出请求、表达承诺、叙述成功，都不等于世界已经改变。
5. 遇到断线或未知结果，先恢复同一 Operation 的回执；不要生成新 Operation 重做一次可能已经完成的动作。
6. 新会话或重新连接先读当前情况与未读变化，再沿用本地记忆。记录过的秘密、技能结果、人物态度不能因换模型而重置。

模型宿主需要把读到的相关内容保留在后续上下文，或在上下文压缩后重新读取。服务器提供章节，不保证任意宿主永远保留它们。不能把“入口可读”“模型已读取”“模型持续主动行动”混为同一验收结论。

## 怎样写规则章节

每章回答：什么时候适用、必要条件、允许效果、谁有权决定、是否掷骰、成功与失败会发生什么、结果怎样确认，以及哪些机制尚未支持。例子用于解释这些规则，不能额外创造规则。

自由表达可映射到现有动作，或组合已有动作。是否需要裁决由要求的效果和规则覆盖情况决定，而不是由输入是否为自然语言决定。

规则确实留下判断空间时，获准裁决者可以提出限定条件、难度和允许的后果。玩家先承诺公开风险，再由服务器掷骰并提交结果。不能先看失败，再取消接受。双方交易与其他玩家的选择仍须由本人作出，裁决者不能代为同意。

裁决说明还要告诉模型如何使用判断空间：可依据当前真实观察与普通常识判断可行性，不要求所有方法已经有专门属性或调查接口。对象、权限、材料等关键条件不能凭空补齐；行动力度、手法等一般不确定可进入检定。允许效果能表达主要后果时，用已有机制给明确报价；无法表达不可省略的核心后果时，说明缺项和实际可行的下一步。未实现的非核心细节应公开范围，不能变成永久阻断，也不能在叙述中假装已经实现。

角色发言、猜测和承诺应与权威事实区分。已经确定的秘密和历史不能随模型叙述改写。尚未支持的机制应明确说明，不得伪装成游戏内的失败。

## 权限与网页

章节读取也服从权限。公开索引可以说明存在裁决者章节，但不能包含幕后秘密或其内容。私有事实与裁决者资料由后端检查身份和授权后返回；隐藏网页按钮不构成权限隔离。

网页与外部工具使用同一套世界动作。网页可以呈现场景、角色、对象、选项、自由输入、骰子结果和历史；选项必须对应真实能力，不能让模型随意生成带权限的函数调用。离开网页不会自动停止外部工具，也不会撤销它的凭据。

## 本轮应用与来源

本轮说明书用于 [旧灯塔第五版规则切片](DND_WORLD.md)，章节源为 [dnd_handbook.py](../examples/dnd_handbook.py)。公开章节为 `index / entry / checks / combat / actions / authority / recovery`；`gm` 由后端授权后提供。D&D 规则的适配范围与场景规则必须区分。

旧灯塔中的静态说明必须随实际函数 schema 同步：普通技能检定与自由裁决的基础属性检定不同；稳定 0 HP 的 `recover`、短休和长休不同；个人故事时钟不代表全世界同步时间或自然跨日；自由裁决的后端固定 `terms` 不能被模型文字覆盖。新增世界采用其他规则时重新定义这些内容，不把本例的职业、骰子、角色或主持人变成 Runtime 固有对象。

参考厂商公开做法：

- [OpenAI Codex 基础指导文件](https://github.com/openai/codex/blob/main/codex-rs/models-manager/prompt.md)：明确环境、工具使用、行动与验证责任。
- [Anthropic 系统提示词总览](https://platform.claude.com/docs/en/release-notes/system-prompts/overview)：公开产品指导与环境说明。
- [Anthropic 上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：预先给必要内容，其他内容通过工具及时取得。

这里采用的是分层说明与按需获取原则，不依赖未经核实的泄露文本或所谓数十万字长度。
